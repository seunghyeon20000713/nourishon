# NourishOn

신체 정보와 식사 기록을 바탕으로 근거 있는 식생활 개선을 돕는 웹 서비스를 만드는 프로젝트입니다.

19~64세 일반 성인을 대상으로 하는 로컬 개발 버전입니다. 현재는 아래 기능이 연결되어 있으며, PostgreSQL 저장·가입·로그인·일반 성인 활동 계획까지 연결했습니다. 챗봇·외부 서비스 배포는 아직 구현하지 않았습니다.

## 현재 가능한 작업

| 화면·기능 | 구현 상태 |
| --- | --- |
| 영양 대시보드 | 선택한 3번 시안의 좁은 메뉴·영양 비율 차트·주간 기록·근거 해석·식사 바로가기 |
| 개인 프로필 | 로그인 계정별 프로필 등록·전환, 프로필별 기록 분리; 로컬 임시 모드 유지 |
| 내 몸과 목표 | 나이·키·체중·활동·관리 방향, 선택 인바디, BMI·유지 에너지·영양 참고값 |
| 체중·인바디 이력 | 측정일별 체중·체성분 등록, 체중 변화 그래프와 원본 표 |
| 음식 검색·계산 | 공공 식품 검색, 섭취량(g) 입력, 한 끼 영양 합계 |

로그인 계정은 사용자별 DB 기록을 구분합니다. 미로그인 로컬 프로필 전환은 접근 제한 기능이 아닙니다. 기존 로컬 기록을 로그인 계정으로 자동 전송하지 않습니다. 공용 기기에서는 개인 기록을 보관하지 마세요. 외부 공개 전에는 HTTPS 등 운영 환경 보완이 필요합니다.

## 영양 계산

계산식은 `100g당 영양성분 × (섭취량(g) ÷ 100)`입니다. 1회 제공량당 값과 혼동하지 않아야 합니다.
연습용 값으로 200kcal/100g을 150g 섭취하면 300kcal입니다. 실제 식품 데이터가 아닙니다.
섭취량이 0g이면 0을 반환하고, 영양성분이나 섭취량이 음수이면 `ValueError`를 발생시킵니다.
입력은 일반 정수·실수만 허용합니다. 결측값(`None`), 문자열, 참/거짓 등은 `TypeError`로 거부하며 자동 변환하지 않습니다.
NaN(유효한 숫자가 아님), 무한대, 음수, 표현 범위를 넘는 입력·계산 결과는 `ValueError`로 거부합니다.
결측값과 0은 다릅니다. 데이터 정제 시 결측값을 임의로 0으로 바꾸지 않습니다.
결과 단위는 100g당 영양성분의 입력 단위와 같습니다. g·mg 자동 변환이나 영양 기준 판정은 수행하지 않습니다.
계산은 부동소수점(근삿값)을 사용하며 원래 값을 보관하고 화면에서 표시용 반올림을 적용합니다.

## 테스트

의존성을 설치한 프로젝트 가상환경에서 다음 명령으로 재검증할 수 있습니다.

```bash
.venv/bin/python -B -m unittest discover -s tests -v
```

백엔드 검증은 가상 입력을 사용하므로 원본 식품 파일 없이도 실행할 수 있습니다. API 테스트에는 `requirements.txt`의 의존성이 필요합니다. 브라우저 시나리오는 로컬 서버와 정제본을 사용합니다.

## 폴더 구조

```text
nourishon/
├─ backend/           # 영양 계산·수집·정제·FastAPI
├─ frontend/          # React 웹 화면과 브라우저 테스트
├─ scripts/           # 프론트엔드·PostgreSQL 로컬 도우미
├─ data/
│  ├─ raw/           # 원본 데이터 보관 위치
│  └─ processed/     # 가공 데이터 보관 위치
├─ docs/              # 기획 및 개발 문서
├─ tests/             # 백엔드 자동 테스트
├─ .venv/             # 로컬 Python 가상환경 (Git 제외)
├─ requirements.txt
├─ .gitignore
└─ README.md
```

빈 폴더에는 Git에서 폴더를 보존하기 위한 `.gitkeep`을 두었습니다.
`data/` 안의 실제 파일은 Git에서 제외하고 `raw/`, `processed/`의 `.gitkeep`만 보존합니다.

## Python 환경

Python 3.12.3으로 `.venv`를 생성했습니다. 이후 pip와 로컬 API 실행·테스트용 라이브러리를 설치했습니다. 검증한 의존성 버전은 `requirements.txt`에 고정했습니다.

```bash
source .venv/bin/activate
python --version
```

가상환경 Python은 프로젝트 기준 `.venv/bin/python`입니다.

## 로컬 API 실행

전체 정제본이 로컬에 있는 상태에서 실행합니다. DB는 [설치·실행 안내](docs/accounts-and-storage.md)에 따라 먼저 시작합니다.

```bash
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -B -m uvicorn backend.api:app --host 127.0.0.1 --port 8000 --no-access-log
```

브라우저에서 [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)를 열어 API 요청을 시험할 수 있습니다. 사용자용 프론트엔드 주소는 아래 5173입니다.
데이터 재현 방법과 가상 입력 예시는 [로컬 API 안내](docs/local-api.md)에 있습니다. 서버는 로컬 개발용이며 로그인 사용자의 기록을 PostgreSQL에 저장합니다.

## 로컬 프론트엔드 실행

백엔드가 실행 중인 상태에서 다른 터미널로 실행합니다.

```bash
bash scripts/frontend.sh dev
```

**[http://127.0.0.1:5173/](http://127.0.0.1:5173/)** 첫 화면은 영양 대시보드입니다. 상단 ‘식사 기록’ 또는 왼쪽 ‘식사 분석’에서 음식 검색 → 추가 → 섭취량 입력 → 영양 합계를 확인합니다. 가입·로그인과 로컬 프로필·보관 설정은 상단 계정·프로필 메뉴에 있습니다.
로그인하면 프로필·식사·측정·활동 계획을 PostgreSQL에 저장합니다. 미로그인 상태는 기본 실행 중에만 유지되며, 화면에서 보관을 선택하면 로컬 프로필·기록을 브라우저의 암호화되지 않은 저장소에 보관합니다. 공용 기기에서는 보관하지 마세요. 실행 환경과 다른 컴퓨터의 설치 방법은 [프론트엔드 안내](docs/local-frontend.md)에 있습니다.

## 로컬 MVP에서 가능한 작업

- 음식 검색·섭취량 계산 → 날짜와 식사 구분으로 기록
- 19~64세 일반 성인 프로필, 선택 인바디 입력, BMI와 추정 유지 에너지·일반 영양 참고값
- 날짜별 영양 합계와 최근 7일 기록 현황, 누락과 미기록 구분
- 공식 출처를 표시한 규칙 기반 식사·활동 안내
- 기본 세션 유지, 사용자가 선택한 경우에만 브라우저 보관

계산 근거·제한·검증은 [로컬 MVP 안내](docs/local-mvp.md)를 확인하세요.
체중·인바디는 측정 이력과 체중 변화 그래프까지 제공합니다. 의료적 운동 처방과 인바디 기반 에너지 공식은 구현하지 않았습니다. 일반 성인용 활동 계획 초안은 제공하며 의료적 운동 처방은 제외합니다.

자동 주기 실행은 현재 범위에서 제외합니다. `backend.collect_food_api`를 직접 실행하면 분류별 한 페이지를 수집하고 원본·수집 기록을 로컬에 보존합니다.

DB·가입·로그인은 구현했습니다. 일반 성인 활동 계획을 제공하며, 챗봇·외부 배포·의료적 운동 처방은 아직 구현하지 않았습니다. 로컬 개발용입니다.

작은 기능마다 구현 → 실제 실행·테스트 → 문서 갱신 → 로컬 커밋 → GitHub 푸시 순서로 진행합니다.

## 데이터 및 인증 정보 관리

실제 식품 수집 파일은 `data/`에, 비밀 설정은 `.env`에 보관하고 Git에 올리지 않습니다. 로그인 프로필·식사 기록은 Git에서 제외한 로컬 PostgreSQL에 저장합니다. 미로그인 임시 모드는 브라우저 메모리 또는 직접 선택한 브라우저 저장소를 사용합니다. DB 연결 설정 `.env.database`도 Git에서 제외합니다.
`.env.example`을 만들 경우 실제 키나 개인정보 없이 항목 예시만 작성합니다.
`.gitignore`는 파일 내용을 검사하지 않으므로 문서나 코드에 인증키와 개인정보를 직접 작성하지 않아야 합니다.

화면 적용 기록: [3번 시안 적용](docs/journal-redesign.md), [디자인 QA](design-qa.md).

### 스크롤 소개 화면

로컬 첫 화면(`/`)에서 신체 정보 → 식사 기록 → 영양 해석을 스크롤하며 살펴볼 수 있습니다. **관리 시작하기** 버튼으로 기존 대시보드에 들어갑니다. 관리 화면 바로가기는 `http://localhost:5173/#dashboard`입니다. 소개의 수치는 연습용이며, 모바일 및 동작 줄이기 설정을 지원합니다. [구현과 검증](docs/scroll-introduction.md)을 참고하세요.

### 첫 이용 안내

영양 대시보드에서 선택한 프로필의 **신체 정보 → 추정 목표 계산 → 첫 식사 기록** 상태와 다음 할 일을 확인할 수 있습니다. 각 버튼으로 해당 화면에 이동하며, 준비가 끝나면 안내가 접힙니다. 가입은 필수가 아니며 로컬 기록은 가입 계정으로 자동 업로드하지 않습니다. [안내 기준과 검증](docs/getting-started.md)을 참고하세요.

관리 화면의 N 로고 아래 또는 우측 상단 메뉴 버튼을 누르면 메뉴 이름을 펼쳐 볼 수 있습니다. 메뉴를 선택하거나 Escape를 누르면 접힙니다. [메뉴 동작](docs/navigation-menu.md)을 참고하세요.

‘기록과 분석’에서 **기록 수정**을 눌러 식사 날짜·구분·섭취량을 변경할 수 있습니다. 섭취량 변경 시 현재 식품 데이터로 다시 계산하고, 날짜·구분만 변경하면 당시 영양 값은 유지합니다. [기록 수정 기준](docs/meal-record-editing.md)을 참고하세요.

‘내 몸과 목표’의 **측정 수정·측정 삭제**로 체중·인바디 이력을 관리할 수 있습니다. 이력의 표·그래프만 갱신하며 현재 프로필과 목표는 자동 변경하지 않습니다. [측정 이력 관리 기준](docs/measurement-editing.md)을 참고하세요.

‘기록과 분석’에서 **주간·월간**을 선택하면 같은 기간의 영양 합계·일별 식사 기록·체중과 체성분 변화를 확인할 수 있습니다. 평균의 분모와 누락 정보를 표시하며, 미기록은 0으로 처리하지 않습니다. [기간 분석 기준](docs/period-analysis.md)을 참고하세요.

영양·운동 결과의 **출처·버전·적용 대상 확인**에서 자료의 버전과 적용 한계를 볼 수 있습니다. 운동 조건을 바꾸면 기존 계획을 숨기고 재생성을 안내합니다. [2026-11-06 근거 점검](docs/nutrition-exercise-audit.md)에 공식 기준과 서비스 자체 규칙을 구분해 기록했습니다.

‘운동 계획’ 아래 **실제 운동 기록과 소모량 추정**에서 걷기·러닝·근력·자전거·요가·필라테스·생활 스포츠 등 25개 조건을 선택할 수 있습니다. 19~59세 표준 MET와 당시 체중·시간으로 총 소모량 및 안정 시 제외 값을 구분하며, 계산 후 기록·날짜별 조회·삭제가 가능합니다. [자료 출처·계산·저장 기준](docs/activity-records.md)을 참고하세요.
