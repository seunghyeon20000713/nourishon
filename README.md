# NourishOn

신체 정보와 식사 기록을 바탕으로 근거 있는 식생활 개선을 돕는 웹 서비스를 만드는 프로젝트입니다.

## 현재 준비 상태

- 기본 폴더 구조와 Python 가상환경 `.venv`를 준비했습니다.
- `.gitignore`에 가상환경, 캐시, 인증 정보 및 실제 데이터 제외 규칙을 작성했습니다.
- `backend/nutrition.py`에 100g당 영양성분과 섭취량(g)을 받아 실제 섭취한 영양성분을 계산하는 함수를 작성했습니다. 웹 서비스는 아직 구현하지 않았습니다.
- 외부 라이브러리 설치, 자체 서비스 API, 데이터베이스, Docker, 웹 화면, 챗봇 구현은 진행하지 않았습니다.
- 식약처 공공 API 인증과 첫 페이지 3개 항목의 수동 조회에 성공했습니다. 응답의 전체 결과 수는 341,644건이며 전체 수집은 하지 않았습니다. [연결 확인·오류 해결 기록](docs/public-api-connection.md)을 남겼습니다.
- 재사용 가능한 수동 수집 명령으로 5개 분류에서 20개씩, 고유 식품코드 100개를 확보했습니다. [실행 방법·종류별 수집 결과](docs/manual-api-collection.md)를 기록했습니다.
- 공식 성분 명세에 따라 API 식품 100개를 정제하고 기존 검색·한 끼 계산에 연결했습니다. [필드·단위·결측·날짜 처리와 실제 검증 결과](docs/api-data-normalization.md)를 기록했습니다.
- 로컬 Git과 [공개 GitHub 저장소](https://github.com/seunghyeon20000713/nourishon)를 연결하고 첫 업로드를 완료했습니다.
- 영양 계산·식품 데이터 연결·검색·한 끼 합계·API 수집·정제 자동 테스트 총 39개의 통과를 확인했습니다.
- 공식 다운로드 서비스에서 식품 데이터 100행을 JSON으로 확보하고 검사용 CSV로 변환·검사했습니다. 100g 98행·100mL 2행, 식이섬유 결측 100행을 확인했습니다. 전체 데이터의 특성으로 일반화하지 않습니다.
- 식약처 제공기관 파일의 이용허락범위 표시를 확인했습니다. [확보 경로·적용 범위·실제 검사 결과](docs/public-food-data.md)를 기록했으며 원본·변환 데이터는 Git에서 제외합니다.
- 100g 기준 첫 5개 식품을 선택해 각각 150g의 영양성분을 계산했습니다. [선택 기준과 실행 결과](docs/food-sample-calculation.md)를 기록했으며 추천이나 실제 사용자 식사 기록이 아닙니다.
- 로컬 표본에서 음식명 부분 검색과 정확한 식품코드 선택을 구현했습니다. [검색 실행 방법과 검증 결과](docs/food-search.md)를 기록했습니다. 전체 공공 DB 검색이나 웹 검색 화면은 아직 없습니다.
- 음식별 섭취량으로 한 끼 영양 합계를 계산하고 일부·전체 결측과 누락 개수를 한글로 표시합니다. [직접 실행 방법과 결과](docs/meal-calculation.md)를 확인할 수 있습니다. 식사 저장은 아직 없습니다.

## 영양 계산

계산식은 `100g당 영양성분 × (섭취량(g) ÷ 100)`입니다. 1회 제공량당 값과 혼동하지 않아야 합니다.
연습용 값으로 200kcal/100g을 150g 섭취하면 300kcal입니다. 실제 식품 데이터가 아닙니다.
섭취량이 0g이면 0을 반환하고, 영양성분이나 섭취량이 음수이면 `ValueError`를 발생시킵니다.
입력은 일반 정수·실수만 허용합니다. 결측값(`None`), 문자열, 참/거짓 등은 `TypeError`로 거부하며 자동 변환하지 않습니다.
NaN(유효한 숫자가 아님), 무한대, 음수, 표현 범위를 넘는 입력·계산 결과는 `ValueError`로 거부합니다.
결측값과 0은 다릅니다. 데이터 정제 시 결측값을 임의로 0으로 바꾸지 않습니다.
결과 단위는 100g당 영양성분의 입력 단위와 같습니다. g·mg 자동 변환이나 영양 기준 판정은 수행하지 않습니다.
계산에는 부동소수점(근삿값)을 사용하며 표시용 반올림은 아직 적용하지 않았습니다.

## 테스트

프로젝트 루트에서 다음 명령으로 외부 라이브러리 없이 재검증할 수 있습니다.

```bash
.venv/bin/python -B -m unittest discover -s tests -v
```

총 39개 테스트에서 계산 입력·범위 검증, 식품 표본 선택·단위 보존·결측/0 구분, 음식명 검색·코드 선택·한 끼 합계, API 수집과 비밀값 보호, 정제 매핑과 원본 무결성을 검증했습니다.
테스트 데이터는 실제 식품이 아닌 가상 데이터이므로 원본 파일 없이도 테스트를 실행할 수 있습니다.
세부 규칙과 실행 결과는 [영양 계산 검증 기록](docs/nutrition-calculation.md)에 정리했습니다.

## 폴더 구조

```text
nourishon/
├─ backend/           # 영양 계산 함수
├─ data/
│  ├─ raw/           # 원본 데이터 보관 위치
│  └─ processed/     # 가공 데이터 보관 위치
├─ docs/              # 기획 및 개발 문서
├─ tests/             # 영양 계산 자동 테스트
├─ .venv/             # 로컬 Python 가상환경 (Git 제외)
├─ .gitignore
└─ README.md
```

빈 폴더에는 Git에서 폴더를 보존하기 위한 `.gitkeep`을 두었습니다.
`data/` 안의 실제 파일은 Git에서 제외하고 `raw/`, `processed/`의 `.gitkeep`만 보존합니다.

## Python 환경

Python 3.12.3으로 `.venv`를 생성했습니다. pip 및 외부 라이브러리는 설치하지 않았습니다.

```bash
source .venv/bin/activate
python --version
```

가상환경 Python은 프로젝트 기준 `.venv/bin/python`입니다.

2. 전체 수집 확장은 표본 검증과 수집 실패·재개·호출 한도를 고려해 별도로 진행합니다. 전체 데이터 수집은 아직 하지 않았습니다.
3. 이후 음식 검색·식사 기록 API와 PostgreSQL → 개인 목표 → React 웹 대시보드 → 개선 제안 → 챗봇 → 인증·배포 순으로 확장할 계획입니다.
4. 데이터 구조에서 사용자 구분을 고려하고, 인증 전에는 로컬 단일 사용자 개발용으로 제한합니다.

공공 API 수집·갱신은 개발 단계에서 필요할 때 명령을 직접 실행하는 수동 방식으로 도입합니다.
자동 주기 실행은 현재 범위에서 제외합니다. `backend.collect_food_api`를 직접 실행하면 분류별 한 페이지를 수집하고 원본·수집 기록을 로컬에 보존합니다.
세부 원칙은 [수동 수집·갱신 결정](docs/public-food-data.md#개발-단계의-수동-수집갱신-결정)에 기록했습니다.

위 기술과 챗봇은 향후 계획이며 현재 구현된 기능이 아닙니다.

작은 기능마다 구현 → 실제 실행·테스트 → 문서 갱신 → 로컬 커밋 → GitHub 푸시 순서로 진행합니다.
보고에는 실행 결과와 제한 사항을 포함하고, 데이터·개인정보·인증 정보는 업로드에서 제외합니다.

## 데이터 및 인증 정보 관리

실제 신체 정보와 식사 기록은 `data/`에, 로컬 비밀 설정은 `.env` 등에 보관하고 Git에 올리지 않습니다.
`.env.example`을 만들 경우 실제 키나 개인정보 없이 항목 예시만 작성합니다.
`.gitignore`는 파일 내용을 검사하지 않으므로 문서나 코드에 인증키와 개인정보를 직접 작성하지 않아야 합니다.
