# 주간·월간 기록 분석

‘기록과 분석’의 조회 날짜를 기준으로 주간(월요일~일요일) 또는 달력 월을 선택한다. 기존 최근 7일 버튼 영역을 기간 분석으로 확장했다.

## 식사 집계

- 선택 기간 중 오늘까지 등록한 식사만 합산한다. 미래 날짜는 예정으로 표시하며 누를 수 없다.
- 식사 건수와 기록한 날짜 수를 구분한다.
- 열량 평균은 확인된 열량 합계 / 열량 정보가 하나 이상 있는 기록일 수다. 분모를 명시한다. 실제 하루 전체 섭취량의 평균으로 해석하지 않는다.
- 0 kcal 기록은 값으로 포함한다. 미기록일과 영양 값이 전부 없는 날짜는 평균 분모에서 제외한다.
- 일부 누락된 값은 확인된 값만 합산하고 일부 정보 누락을 표시한다. 영양성분 필드 자체가 없는 이전 기록도 누락으로 처리한다.
- 영양성분별 합계와 정보 상태, 일별 열량을 표시한다. 일별 버튼은 해당 날짜의 상세 기록으로 연결한다. 미기록을 0으로 대체하지 않는다.
- 기간의 열량 기록만으로 영양 부족·과잉 또는 건강 개선을 판정하지 않는다. 개인의 현재 목표를 과거 기간에 일괄 적용하지 않는다.

## 신체 변화

동일 기간 안의 측정 기록만 사용한다. 항목별로 값이 있는 첫날과 마지막 날을 표시하므로 체중·체성분의 비교 날짜가 다를 수 있다. 서로 다른 날짜의 값이 둘 이상일 때만 차이를 계산한다. 같은 날짜의 기록만 있으면 판단을 보류한다. 결측값과 기간 밖 측정값을 대신 채우지 않는다.

체중·골격근량·체지방량 차이는 kg, 체지방률 차이는 퍼센트포인트(%p)로 표시한다. 측정 조건 차이가 있으며 식사와 신체 변화의 인과관계나 건강 개선을 입증하지 않는다.

## 검증

가상 기록으로 윤년 2월·월 경계·연도 경계의 주간, 열량 0·전체 결측·일부 누락, 평균 분모, 체중 -1kg·체지방률 -2%p, 단일 측정 보류, 빈 기간, 상세 이동 및 모바일 가로 넘침을 검사한다. 실제 식품·건강 데이터는 Git에 추가하지 않는다.

실제 검증 결과: TypeScript·Vite 빌드 통과. 전체 브라우저 실행에서 17개 통과, 1개는 일별·기간별 동일 숫자로 인한 검사 선택자 모호성으로 실패했다. 기존 일별 카드 검사 범위를 명확히 한 후 관련 식사·기간 분석 **10개 모두 통과(13.0초)**. 처음 작성한 주간 평균의 기대값은 0 kcal 기록일도 분모에 포함하는 기준에 맞게 500/3=166.67로 바로잡았다. 가상 기록의 데스크톱·390px 모바일 캡처를 직접 확인했다.
