# 로컬 음식 검색·선택

실행일: 2026-11-05. Python 3.12.3 가상환경에서 실행했습니다. 외부 라이브러리 설치 없음.

## 완료 범위와 설계

`backend/food_search.py`의 `search_foods()`는 음식명 부분 일치 검색,
`select_food()`는 정확한 식품코드 선택을 담당합니다.
기존 로컬 원본 JSON 100행을 사용하며 네트워크·API·DB를 호출하지 않습니다.
식품코드가 다르면 이름이 같아도 별도 후보로 유지합니다.

- 검색·선택 모두 기준량이 정확히 100g인 식품만 대상으로 합니다. 100mL 식품의 이름·코드를 입력해도 계산 후보로 반환하지 않습니다.
- 이름 비교 때 유니코드 NFKC 정규화, 영문 대소문자 통일, 앞뒤 공백 제거와 연속 공백 통일을 적용합니다. NFKC는 전각 영문 등 동등한 문자 표현을 맞추는 방식입니다.
- 원본 식품명과 순서는 보존합니다. 이름 내부 공백을 모두 제거하거나 초성·오타·동의어 검색을 하지는 않습니다.
- 빈 검색어는 ValueError, 문자열이 아닌 검색어는 TypeError입니다. 일치 항목이 없으면 빈 목록을 반환합니다.
- 코드는 앞뒤 공백만 제거하고 정확히 비교합니다. 없는 코드·100mL 전용 코드는 LookupError, 중복된 100g 코드는 ValueError로 거부합니다.
- 반환 행은 복사본이므로 반환값을 수정해 원본 행이 바뀌는 것을 방지합니다.
- 명령 실행 시 코드·이름·기준량·출처·기준일만 출력합니다. 음식 기록을 저장하거나 개인 섭취량을 받지 않습니다.

## 재현 방법

프로젝트 루트에서 로컬 원본 파일이 있을 때 실행합니다. 데이터 파일은 Git 제외 대상입니다.

```bash
.venv/bin/python -B -m backend.food_search \
  data/raw/food-standard-15100064-page1-100-20261105.json --query 꿀떡

.venv/bin/python -B -m backend.food_search \
  data/raw/food-standard-15100064-page1-100-20261105.json \
  --food-code P101-501000500-4798
```

## 실제 검증 결과

- 로컬 공식 표본에서 `꿀떡` 검색 → 결과 2개.
- 검색 결과 코드 `P101-501000500-4798` 지정 → 결과 1개.
- 원본 출처 및 확보 기록: [공공 식품 데이터 조사](public-food-data.md).
- `.venv/bin/python -B -m unittest discover -s tests -v` → 기존 13개 + 신규 7개, 총 20개 통과.
- 신규 테스트는 실제 식품이 아닌 가상 행으로 부분 일치·정규화·빈 검색어·미일치·동명 식품 코드 선택·복사본 반환·100mL 제외·중복 코드 거부를 검증합니다.

이번 검색은 전체 공공 식품 DB 검색이 아닌 로컬 100행 중 100g 기준 식품 검색입니다.
페이지네이션·전체 데이터 검색·검색 성능 측정은 구현하지 않았습니다.
다음 단계는 코드로 선택한 식품별 섭취량을 계산하고, 결측을 표시하는 한 끼 합계 기능입니다.
