# NourishOn 한눈에 보기 (2026-11-27 기준)

> 개발자가 이 프로젝트를 스스로 설명할 수 있도록, "무엇을 만들었고 왜 그렇게 만들었는지"를 한 장으로 정리한 문서.

## 1. 한 줄 소개

**식사·운동·몸 기록을 바탕으로, 근거 있는 숫자와 쉬운 설명을 주는 개인 건강 기록 웹서비스.**
영양사 관점의 원칙(결측과 0을 구분, 공식 기준과 출처 표시, 진단하지 않음)을 코드와 테스트로 지키는 것이 핵심이다.

- 실제 기능 테스트 서버: https://nourishon-staging.onrender.com (무료 서버라 첫 접속 1~2분)
- 규모: 커밋 79개, 백엔드 테스트 파일 24개(173개 테스트), 브라우저 테스트 파일 20개(40개 테스트), 면접 노트 17개

| 화면 | 할 수 있는 일 | 숨은 원칙 |
| --- | --- | --- |

| 내 정보·계정 | 키·체중·활동량으로 유지 에너지 참고값, 가입·로그인·회원 탈퇴 | 2025 한국인 영양소 섭취기준·WHO 출처 표시 |

## 3. 어떻게 돌아가나 (구조)

```
[브라우저 화면]  React + TypeScript (Vite)
      │  /api 요청 (로그인 쿠키 + CSRF 토큰)
      ▼
[서버]  Python FastAPI ─────────────┬─ 식품 검색: SQLite 임시 파일(29만 건, 메모리 절약)
      │                            ├─ 계산 함수: 영양 합계·기간 분석·운동 소모량·참고값
      │                            └─ 건강 비서: 도구 5개 → AI 제공자(가짜 AI / Gemini)
      ▼
[DB]  PostgreSQL (회원·프로필·식사·체중·운동·질문 수)
```

배포(모두 무료):
```
GitHub ──push──▶ GitHub Actions(PostgreSQL 16·18에서 테스트) ──✓──▶ Render 수동 배포
                                                                 ├─ 식품 데이터: 비공개 GitHub Release(토큰 + SHA-256 검증)
                                                                 └─ DB: Neon 무료 PostgreSQL 18
```

## 4. 꼭 설명할 수 있어야 하는 설계 7가지

1. **결측 ≠ 0** — 성분 정보가 없으면 0으로 채우지 않고 "누락 N개", 기록 안 한 날은 평균에서 뺀다. 체성분 미입력이 0.0으로 보이던 버그도 이 원칙으로 찾았다.
2. **AI는 계산하지 않는다** — 숫자는 테스트된 함수(도구)가 만들고 AI는 설명만 한다. AI 문장에 도구 결과에 없는 숫자가 나오면 자동으로 기본 설명으로 바꾼다.
3. **AI 제공자 분리** — 가짜 AI(규칙 기반, 0원, 외부 전송 없음)와 Gemini를 설정 하나로 바꾼다. Gemini가 실패하면 가짜 AI가 대신 답한다.
4. **본인 기록만, 보내는 값은 최소로** — 도구에 사용자 ID 입력이 없고 서버가 세션으로 본인 것만 넘긴다. 외부 AI에는 질문과 숫자만, 아이디·닉네임·음식 이름은 빠지는지 테스트로 확인한다.
5. **보안 기본기** — 비밀번호 argon2, HttpOnly 쿠키 + CSRF, SQL은 항상 값 바인딩, 로그인 시도 제한(실제 사용자 IP), 회원 탈퇴 시 기록 전부 삭제.
6. **무료로 운영하기** — Render·Neon 무료, 식품 원본은 Git에 두지 않고 비공개 Release에서 내려받아 SHA-256으로 검증, AI는 무료 등급 + 하루 질문 수 제한.
7. **측정하고 바꾸기** — 디자인 개선 전후 캡처, 검색 순위는 실제 데이터로 비교해 요청 방식이 결과를 나쁘게 하면 방식을 바꿨다(면접 노트 12).

## 5. 품질을 지키는 방법

- **백엔드 테스트(unittest)**: 계산·검색·계정·건강 비서 안전장치. DB 테스트는 별도 테스트 DB에서만.
- **브라우저 테스트(Playwright)**: 실제 화면을 데스크톱·모바일(390px)로 조작해 확인(가로 넘침, 포커스, 접근성 포함).
- **CI**: GitHub에 올릴 때마다 PostgreSQL 16·18 두 버전에서 자동 실행, 건너뛴 테스트가 있으면 실패 처리.
- **문서**: 기능마다 `docs/`에 설계 문서, `docs/interview-notes.md`에 면접용 정리.

## 7. 면접에서 30초로 소개하면

> "영양사로서 식사 기록 앱들이 빠진 정보를 0으로 계산하는 문제를 보고, 결측과 0을 구분하는 건강 기록 서비스를 만들었습니다. FastAPI와 PostgreSQL, React로 만들고 무료 클라우드에 배포했으며, 테스트 200여 개를 CI로 돌립니다. 최근에는 LLM이 숫자를 직접 만들지 않고 테스트된 계산 함수를 도구로 부르는 건강 비서를 붙였고, 외부 AI로 보내는 정보를 테스트로 제한했습니다."
