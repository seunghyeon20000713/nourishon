# 공공 식품 데이터 도입 조사

확인일: 2026-11-05. 공식 다운로드 서비스의 100행 JSON 표본 확보와 검사용 CSV 변환·기초 검사를 완료했습니다.
공식 CSV 파일 자체를 받은 것은 아닙니다. 후속 단계에서 [100g 기준 5개 식품의 150g 계산 연결](food-sample-calculation.md)을 완료했습니다. 인증키를 사용하는 공공 API 연결은 아직 수행하지 않았습니다.

## 공식 후보와 확인 결과

첫 파일 기반 검증 후보는 공공데이터포털의 [전국통합식품영양성분정보표준데이터](https://www.data.go.kr/data/15100064/standard.do)입니다.

- [공식 메타데이터](https://www.data.go.kr/catalog/15100064/standard.json)에서 식별자 15100064, CSV 등 파일 형식 제공을 확인했습니다. 조회된 메타데이터 수정일은 2026-11-02입니다. 이는 다운로드한 파일 버전이나 개별 행의 기준일을 의미하지 않습니다.
- 식품코드·식품명·영양성분함량기준량, 에너지(kcal), 단백질·지방·탄수화물·당류·식이섬유(g), 나트륨(mg), 출처명 등 항목이 안내됩니다. 실제 파일의 열 이름과 값은 다운로드 후 별도로 확인해야 합니다.
- 식약처 [K-FIND 다운로드 안내](https://various.foodsafetykorea.go.kr/nutrient/general/down/list.do)에서도 파일 다운로드와 공공데이터포털의 통합 DB를 안내합니다.
- 이후 API 후보는 [식품의약품안전처 식품영양성분DB정보](https://www.data.go.kr/data/15127578/openapi.do)입니다. [API 메타데이터](https://www.data.go.kr/catalog/15127578/openapi.json)에는 이용허락범위 제한 없음으로 표시되지만, 이를 별도 파일의 재배포 허용 근거로 대체하지 않습니다. 이번에는 API를 신청하거나 호출하지 않았습니다.

## 최초 조사에서 확인하지 못했던 사항

웹 조회 도구에서 표준데이터 상세 페이지 본문을 읽을 때 `Unsupported content-type: text/markdown` 오류가 발생했습니다. 공식 검색 결과와 메타데이터로 제공 항목을 확인했지만, 선택할 실제 다운로드 파일의 구체적인 이용허락범위는 확정하지 못했습니다.
표준데이터 메타데이터에는 이용정책 링크가 있지만 구체적인 라이선스 명칭은 없습니다. 무료 제공과 재배포 허용은 구분합니다.
파일 이용 조건·출처 표기 요구를 확인한 뒤 필요한 공개 샘플의 Git 포함 여부를 판단합니다. 현재는 데이터 파일을 공개하지 않습니다.

후속 확인에서는 curl로 공식 HTML을 받아 위 본문 조회 오류를 해결했습니다. 식약처 제공기관 파일 상세에 표시된 이용허락범위도 확인했습니다. 구체적인 결과와 적용 범위는 아래 실행 기록에 구분했습니다.

## 첫 소량 검증 계획

다음은 데이터에 이미 적용한 결과가 아닌 프로젝트의 처리 규칙입니다.

1. 공식 CSV와 해당 이용 조건을 확보하고 `data/raw/`에 보관합니다. 파일명, 다운로드 날짜, 원본 URL, 파일 SHA-256, 표기된 버전 및 데이터 기준일을 기록합니다. SHA-256은 같은 파일인지 확인하기 위한 내용 식별값입니다.
2. 열 이름·인코딩·총 행 수·기준량별 행 수·주요 성분의 결측 수를 확인합니다. 원본은 수정하지 않습니다.
3. `100g` 기준임을 확인한 식품 5~10개를 골라 `data/processed/`에 저장하고 기존 함수로 150g 섭취량을 계산합니다. 실제 선택한 식품코드와 선택 이유를 기록합니다.

### 정제 후 필요한 항목

| 항목 | 처리 원칙 |
|---|---|
| 식품코드·식품명 | 이름만으로 합치지 않고 코드와 원본 행을 추적 |
| 영양성분 함량 기준량 | 첫 버전은 100g만 허용. 100mL·1회 제공량·알 수 없는 기준은 제외 사유 기록 |
| 에너지 | kcal 유지 |
| 단백질·지방·탄수화물·당류·식이섬유 | g 유지 |
| 나트륨 | mg 유지. g으로 표시할 경우 명시적인 변환 필요 |
| 결측값 | 빈 값은 결측으로 유지. 해당 성분의 계산 결과도 미확인으로 표시할 계획 |
| 숫자 0 | 결측과 구별해 유효한 0으로 보존 |
| 특수 표기 | 흔적량·미검출·범위 등은 임의로 숫자나 0으로 치환하지 않고 원본 표기와 사유 보존 |
| 출처·생성 방법·기준일 | 제공된 원본 정보를 함께 보존. 누락되면 추정하지 않음 |

100mL를 100g으로 간주하지 않습니다. 식품중량이나 제품 총량도 영양성분 기준량과 구분합니다.
현재 계산 함수는 결측을 거부하므로 정제·연결 단계에서 결측 성분을 함수에 전달하지 않는 처리가 필요합니다.
영양성분이 빠진 기록은 향후 합계에서 제외됐다는 사실과 누락 개수를 표시해야 하며, 완전한 하루 섭취량으로 해석하지 않습니다.

## 공개와 보관

`data/`의 실제 파일은 현재 Git 제외 상태를 유지합니다. 개인 건강정보와 식사 기록을 공공 식품 데이터에 섞지 않습니다.
이번 공개 대상은 출처 링크와 설계 문서뿐입니다. 원본 데이터와 API 키는 포함하지 않습니다.

## 개발 단계의 수동 수집·갱신 결정

결정일: 2026-11-05. 사용자 요청에 따라 개발 중 공공 API 수집·갱신은 필요할 때 명령을 직접 실행하는 방식으로 도입합니다.
자동 예약 실행은 현재 구현 범위에서 제외합니다. 수동이란 데이터를 손으로 복사한다는 뜻이 아니라 수집 프로그램을 직접 시작한다는 뜻입니다.
아래는 향후 구현 원칙이며, 현재 API 키 설정·인증 API 호출·수집 명령·갱신 기능은 구현하지 않았습니다.

- API 키는 로컬 비밀 설정에 보관하고 출력·문서·Git에 포함하지 않습니다. 요청 주소 기록에도 키를 남기지 않습니다.
- 실행마다 수집일, 출처, 비밀값을 제외한 조회 조건, 수집 건수, 제공 데이터 기준일과 원본 파일 해시를 남깁니다. 별도 기준일이 없으면 추정하지 않습니다.
- 원본은 실행별로 보존하고 이전 파일을 덮어쓰지 않습니다. 페이지 수집 범위와 실패 여부를 기록하고 전체 수집 완료를 추정하지 않습니다.
- 새 수집본은 열·단위·결측·중복 코드 등을 검증한 뒤 검색·계산용 데이터로 반영합니다. 수집 실패나 검증 실패 시 기존 사용 데이터를 유지합니다.
- 새 식품 데이터가 과거 식사 계산 결과를 자동으로 바꾸지 않도록, 식사 저장을 구현할 때 당시 사용한 영양값과 출처·기준일을 보존합니다.
- 데이터 수집과 로컬 서비스 실행은 분리합니다. 웹을 시작하거나 검색할 때마다 공공 API를 호출하지 않는 구조를 목표로 합니다.

자동 갱신은 필요성이 확인된 이후 별도 작업으로 검토합니다. 현재 로컬 100행 표본과 기존 기능은 그대로 사용합니다.

## 표본 확보 및 실제 검사 결과 — 2026-11-05

### 확보 경로와 이용 조건

공식 페이지의 [다운로드 스크립트](https://www.data.go.kr/js/biz/mvc/std/std-download-manager.js)를 확인했습니다.
CSV 버튼은 열 정보를 `/download/columList.json?pk=15100064&ext=CSV`에서 받고, 데이터를 `/download/standard.json`에서 받아 브라우저에서 CSV를 생성합니다. 사이트는 EUC-KR 인코딩을 사용하지만, 이번 검사용 CSV는 UTF-8 BOM으로 생성했습니다.
공식 브라우저 생성 CSV와 이번 CSV의 바이트가 같다고 주장하지 않습니다.

데이터 요청은 위 열 정보의 `tableVO.colNmList`를 반복 파라미터 `colNmList`로 전달하고, `publicDataPk=15100064`, `svcTableNm=tn_pubr_public_nutri_info_svc`, `totalCount=50000`, `perPage=100`, `page=1`을 사용했습니다.
5만은 다운로드 제한값으로, 전체 데이터 건수로 해석하지 않습니다. 이번 요청에는 인증키가 없으며 사이트 다운로드 서비스만 이용했습니다.

식약처 파일의 이용허락범위는 공식 상세 요청 `/tcs/dss/selectDpkDetailInfo.do`에 POST로 `publicDataDetailPk=uddi:8afb7f21-b602-48c8-854f-ea48b2d3224e`를 전달해 확인했습니다.
응답의 ‘이용허락범위’ 항목은 ‘이용허락범위 제한 없음’이었습니다. 이 확인을 농진청·해수부 파일이나 전체 병합 데이터의 재배포 조건으로 일반화하지 않습니다.
이번 표본의 출처명은 모두 식약처입니다. 재배포 여부와 별개로 원본·변환 파일은 이번 커밋에서 제외합니다.

### 재검사 명령과 검증

원본과 열 정보가 있는 로컬 환경의 프로젝트 루트에서 실행합니다. 출력 경로는 새 폴더를 사용합니다. 이 명령은 네트워크를 호출하지 않습니다.

```bash
.venv/bin/python -B backend/inspect_food_data.py \
  data/raw/food-standard-15100064-page1-100-20261105.json \
  data/raw/food-standard-columns-20261105.json \
  data/processed/inspection-20261105-repeat
```

Python 3.12.3 가상환경에서 실행했고 추가 라이브러리는 설치하지 않았습니다.
CSV를 다시 읽어 100행 × 47열을 원본 JSON과 대조해 일치를 확인했습니다. 다른 출력 폴더의 요약도 일치했고, 기존 CSV 덮어쓰기와 빈 원본·잘못된 열은 거부했습니다.
이 검사는 CSV 변환의 보존 여부를 확인한 것이며 영양성분 값 자체의 과학적 정확성을 검증한 것은 아닙니다.
기존 영양 계산 자동 테스트 7개도 모두 통과했습니다.

후속 단계에서 100g 기준 5개 음식을 선택하고, 결측을 유지하면서 150g 섭취량을 계산해 검증했습니다. 상세 결과는 [계산 연결 기록](food-sample-calculation.md)에 있습니다.
