# 전체 식품 데이터의 100g 기준 정제

실행일: 2026-11-05. Python 3.12.3 가상환경 사용. 추가 라이브러리 설치나 API 재호출 없음.

## 입력과 처리 방식

[전체 수집 기록](full-api-collection.md)의 원본 684페이지, 341,644개를 처리했습니다.
`backend/normalize_full_food_api.py`는 페이지별 해시·수신 건수·페이지 번호와 전체 코드 중복을 확인하며 처리합니다. 원본 전체를 한 번에 메모리에 올리지 않습니다.
정제 결과는 기존 `food_search.py`와 `meal.py`에서 읽는 JSON 목록입니다.
사용한 성분 매핑은 [공식 명세 확인 기록](api-data-normalization.md)과 같습니다.

## 처리 규칙과 설계 선택

- 100g만 기존 g 기반 계산 목록으로 변환합니다. 100mL·다른 중량/부피·해석이 어려운 기준량은 제외 파일에 원본 위치와 함께 남깁니다.
- `1,315.000` 같은 천 단위 표기는 정규식으로 묶음 형식을 확인한 뒤 쉼표만 제거합니다. `1,23`처럼 잘못 묶인 값은 임의 보정하지 않습니다.
- 빈 값은 null로 보존합니다. 숫자 0과 구분하고 기존 한 끼 계산의 누락 표시를 유지합니다.
- 영양값 g가 100g 초과, 나트륨이 100,000mg 초과, 열량이 프로젝트 검토 임계값 1,000kcal/100g 초과인 식품은 검토 목록에 분리합니다.
- 위 규칙은 보수적 데이터 점검을 위한 프로젝트 규칙이며 공식 영양 기준·진단 기준·검증된 이상 탐지 모델이 아닙니다. 검토 대상 50개를 모두 오류라고 확정하지 않습니다. 반대로 규칙을 통과했다고 값의 과학적 정확성이 보장되는 것도 아닙니다.
- 숫자 형식 오류·필수 열 누락도 검토 목록에 남기고 조용히 0으로 바꾸지 않습니다.
- 원본 파일명·파일 내 행 번호·전체 원본 내 행 번호와 생성일·수정일을 유지합니다. 별도 기준일이 없으므로 기존 기준일 항목은 null입니다.
- 중간 실패 시 `foods.json`을 게시하지 않고 임시 파일과 실패 보고서를 남깁니다. 기존 출력 폴더는 덮어쓰지 않습니다.

## 실제 건수

| 구분 | 개수 |
|---|---:|
| 전체 입력 | 341,644 |
| 검색·계산용 100g 정제본 | 290,871 |
| 기준량 미지원으로 분리 | 50,723 |
| 값 검토를 위해 분리 | 50 |

세 결과 건수의 합은 전체 입력과 일치합니다. 기준량 분리에는 100mL 50,661개와 그 외 표기 62개가 포함됩니다.
검토 사유는 열량 7개, 당류 2개, 나트륨 5개, 탄수화물 30개, 지방 6개입니다.
출력 식품 구분은 음식 10,994개, 원재료성 3,604개, 가공식품 276,273개입니다.

### 검색·계산용 정제본의 결측과 0

분모는 출력 290,871개이며 제외·검토 항목의 값은 포함하지 않습니다.

| 성분 | 결측 | 숫자 0 |
|---|---:|---:|
| 열량 | 2 | 377 |
| 단백질 | 4 | 17,055 |
| 지방 | 8,619 | 26,546 |
| 탄수화물 | 8,390 | 6,440 |
| 당류 | 1,472 | 35,852 |
| 식이섬유 | 279,168 | 1,556 |
| 나트륨 | 516 | 17,707 |

식이섬유의 결측이 많으므로 현재 데이터만으로 모든 식품의 식이섬유 섭취가 충분한지 단정할 수 없습니다.
향후 분석·제안에도 결측 범위와 합계의 불완전성을 전달해야 합니다. 이번에는 다른 식품의 값으로 결측을 채우지 않았습니다.
출력에 포함한 쉼표 숫자 변환은 나트륨 22,824개, 열량 4개입니다.

## 실제 검증

- `.venv/bin/python -B -m unittest discover -s tests -q` → 기존 46개 + 신규 6개, 총 52개 통과.
- 신규 테스트는 올바른/잘못된 쉼표 숫자, 단위·결측·0 보존, 미지원 기준량·검토 대상 분리, 원본 변조·페이지 간 중복·덮어쓰기 거부를 가상 데이터로 확인했습니다.
- 실제 출력 전부를 줄 단위로 읽어 원본 위치·코드·기준량·날짜·성분 변환값을 대조했습니다. 290,871개 × 7성분 = 2,036,097개 결과가 일치했습니다.
- 이 중 결측 298,171개는 None으로 보존됐습니다. 숫자 값은 Decimal로 원본을 별도 해석하고 150g 환산 결과까지 대조해 차이 0.000000001 미만임을 확인했습니다.
- 정제본에서 `국밥_콩나물` 검색 → 1개 결과.
- 돼지머리국밥 코드의 가상 섭취량 150g → 열량 205.5kcal, 단백질 10.05g, 나트륨 271.5mg. 권장 식사량이나 개인 기록이 아닙니다.

## 로컬 실행과 보관

```bash
.venv/bin/python -B -m backend.normalize_full_food_api \
  data/raw/mfds-api-full-20261105-size500 \
  data/processed/mfds-api-full-normalized-20261105

.venv/bin/python -B -m backend.food_search \
  data/processed/mfds-api-full-normalized-20261105/foods.json --query 국밥_콩나물
```

출력은 `foods.json`, `excluded-basis.jsonl`, `quarantine.jsonl`, `report.json`입니다. JSONL은 한 줄에 한 항목을 저장하는 형식입니다.
실제 정제 파일은 약 149.4MB이며 웹 브라우저에 통째로 내려주는 용도로 설계한 것이 아닙니다. 이후 서버에서 검색·페이지 분할을 처리할 계획입니다.
모든 원본·가공 파일·검토 목록은 Git 제외 상태로 로컬에 보관하고, 코드·가상 테스트·문서만 공개합니다.

다음 단계는 최소 FastAPI 검색·계산 기능과 로컬 웹 화면입니다. 100mL 계산과 기타 기준량 해석은 별도 작업으로 남깁니다.
