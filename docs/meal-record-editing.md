# 식사 기록 수정

기록과 분석 화면의 각 식사에 ‘기록 수정’을 추가했다. 날짜·식사 구분·기록된 음식의 섭취량(g)을 수정한다. 음식 추가·교체는 이번 범위가 아니다.

- 날짜·구분만 변경하면 당시 영양 값과 출처 스냅샷을 유지한다.
- 섭취량 변경은 기존 식품 코드로 `/meals/calculate`에 요청하고 해당 식사의 모든 영양성분을 현재 데이터로 다시 계산한다. 따라서 데이터 갱신 시 과거 값과 달라질 수 있음을 화면에 안내한다.
- 식품 코드가 없는 이전 기록은 날짜·구분만 수정할 수 있다.
- 음수·빈 값·비정상 숫자는 적용하지 않는다. 0g은 허용하며 결측값을 0으로 대체하지 않는다. 미래 날짜는 허용하지 않는다.
- 계산 실패나 취소는 원본을 변경하지 않는다. 취소·화면 이탈 시 진행 중 요청을 중단한다.
- 날짜 변경 후에는 변경한 날짜를 조회한다. 기록 ID를 유지하고 새 기록을 중복 추가하지 않는다.
- 로그인 시 기존 계정별 저장 큐로 저장하며 전역 DB 저장 상태를 표시한다. 로그인 전에는 기존 로컬 보관 설정을 따른다.

## 확인

브라우저에서 취소 시 원본 유지, 음수 거절, 섭취량 재계산, 식사 구분 변경, 서버 오류 시 원본 유지, 0g, 모바일 가로 넘침을 검사한다. 계정 시나리오에는 수정 후 PostgreSQL 저장·새로고침 재조회를 추가했다.

실제 실행 결과: 프런트엔드 빌드 통과, 전체 브라우저 **16개 통과(40.5초)**. 날짜만 변경할 때 재계산 요청이 없고 기존 영양 합계를 유지하며 변경 날짜로 조회하는 검사를 추가한 뒤 해당 시나리오 **1개 통과(3.8초)**. 초기 검증에서 식사 구분 선택기의 이름이 모호해 멈춘 문제는 명시적 접근성 이름을 지정하여 해결했다.
