# API 식품 100개 정제와 계산 연결

확인·실행일: 2026-11-05. Python 3.12.3 가상환경 사용. 추가 라이브러리 설치 없음.

## 공식 성분 명세 확인

[공공데이터포털의 식약처 API 페이지](https://www.data.go.kr/data/15127578/openapi.do)의 HTML에 포함된 `swaggerJson`을 추출해 응답 스키마의 항목 설명을 확인했습니다.
공식 명세 스냅샷은 로컬 `data/raw/mfds-api-schema-20261105.json`에 보관합니다.
외부 블로그나 성분 번호의 추정으로 매핑하지 않았습니다.

| API 항목 | 공식 의미·단위 | 기존 계산용 항목 |
|---|---|---|
| AMT_NUM1 | 에너지(kcal) | ENERC |
| AMT_NUM3 | 단백질(g) | PROT |
| AMT_NUM4 | 지방(g) | FATCE |
| AMT_NUM6 | 탄수화물(g) | CHOCDF |
| AMT_NUM7 | 당류(g) | SUGAR |
| AMT_NUM8 | 식이섬유(g) | FIBTG |
| AMT_NUM13 | 나트륨(mg) | NAT |

공식 `SERVING_SIZE`는 영양성분 함량 기준량입니다. `RESEARCH_YMD`는 생성일, `UPDATE_DATE`는 수정일입니다.
수정일을 기준일로 바꾸지 않습니다. 변환본의 기존 `CRTR_YMD`는 null로 두고 생성일·수정일을 별도로 보존합니다.
섭취량 계산 결과에도 생성일·수정일을 전달하도록 `prepare_food_sample.py`를 보완했습니다.

## 변환 규칙

`backend/normalize_food_api.py`는 완료된 수집본의 원본 해시와 건수를 확인한 뒤 기존 검색·계산 함수가 읽는 JSON 목록을 생성합니다.
이전 표본과 형식을 맞추되 원본은 수정하지 않습니다. 파일별 원본 해시·매핑 버전도 보고서에 남깁니다.

- 기준량이 정확히 100g인 식품만 변환하고 나머지는 코드·원본 행 번호·사유를 보고서에 기록합니다.
- 숫자 문자열은 숫자로 변환합니다. g·mg을 자동으로 서로 바꾸지 않습니다.
- 공백·빈 문자열·None은 null로 보존합니다. 숫자 0과 구별합니다.
- 필수 열 누락, 숫자가 아닌 특수 표기, 음수·비유한 값, 식품코드 중복은 오류 처리합니다. 추정하거나 0으로 채우지 않습니다.
- 식품코드·원본 식품명·분류·출처·생성 방법·생성일·수정일·전체 원본 내 행 번호를 유지합니다.
- 미완료 수집본, 해시 불일치·건수 불일치를 거부합니다. 기존 출력 폴더를 덮어쓰지 않습니다.

## 실행 방법

기존 로컬 수집본이 있는 프로젝트 루트에서 실행합니다. 인터넷이나 인증키를 사용하지 않습니다.

```bash
.venv/bin/python -B -m backend.normalize_food_api \
  data/raw/mfds-api-20261105-171230-449195 \
  data/processed/mfds-api-normalized-20261105

.venv/bin/python -B -m backend.food_search \
  data/processed/mfds-api-normalized-20261105/foods.json --query 국밥

.venv/bin/python -B -m backend.meal \
  data/processed/mfds-api-normalized-20261105/foods.json \
  --food D101-004160000-0001 150
```

생성 파일은 `foods.json`(검색·계산용 목록), `report.json`(원본 해시·건수·제외·결측·0 집계)입니다.
이미 출력 폴더가 있으면 새 경로를 사용합니다. 원본·가공 데이터 모두 Git 제외 상태입니다.

| 단백질 | 0 | 0 |

| 탄수화물 | 1 | 0 |

결측률의 분모는 각각 이번 표본 100개입니다. 전체 식품 DB의 품질로 일반화하지 않습니다.

## 실제 검증 결과

- 자동 테스트: `.venv/bin/python -B -m unittest discover -s tests -v` → 기존 33개 + 신규 6개, 총 39개 통과.
- 신규 테스트는 가상 데이터로 매핑, 단위, 날짜 구분, 검색·한 끼 연결, 결측/0 구분, 기준량 제외, 오류 값·누락 열·중복 거부, 원본 해시·미완료 수집본 거부, 덮어쓰기 방지를 검증합니다.
- 실제 100개 식품 각각 150g을 계산해 총 700개 성분 결과를 원본과 대조했습니다. 결측 8개는 결과 None, 나머지는 Decimal로 원본 값 × 1.5를 계산해 차이 0.000000001 미만으로 일치했습니다.
- 정제본에서 `국밥` 검색 → 3개 결과를 확인했습니다.

실제 원본 중 밥류와 과일류 첫 식품을 각각 150g·100g으로 계산한 예시입니다. 권장 식단이나 개인 기록이 아닙니다.
