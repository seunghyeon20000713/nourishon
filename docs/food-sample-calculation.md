# 공식 표본의 섭취량 계산 연결

실행일: 2026-11-05. Python 3.12.3 프로젝트 가상환경 사용. 추가 라이브러리 설치 없음.

## 입력과 선택 기준

[공공데이터 확보 기록](public-food-data.md)의 로컬 원본 JSON 100행을 사용했습니다.
원본 SHA-256은 `25107588591d7ba4be1a7f61f10c6ed27fc5ffb085bb2e434fcef2110f7df7fe`입니다.
공식 출처는 [전국통합식품영양성분정보표준데이터](https://www.data.go.kr/data/15100064/standard.do)이며 이 표본의 출처명은 식품의약품안전처, 데이터 기준일은 2026-10-29입니다.

기준량이 정확히 `100g`인 첫 5개 식품을 원본 순서대로 선택했습니다. 100mL는 g으로 환산하지 않습니다.
이 방식은 계산 연결을 재현하기 위한 것으로 일반 식사의 대표성이나 건강식 추천을 의미하지 않습니다. 특정 제품의 품질·효능도 평가하지 않습니다.
150g은 프로젝트의 동일 조건 비교용 가상 섭취량이며 권장 섭취량·제품 1회 제공량·실제 개인 식사 기록이 아닙니다.

선택한 원본 행 번호는 1, 2, 3, 5, 7입니다. 식품코드는 다음과 같습니다.

```text
P123-205020300-2649
P114-300030000-2318
P114-400020100-0604
P108-012000200-0001
P101-501000500-4798
```

식품명과 전체 원본·계산 파일은 로컬에서 확인하며 이번 커밋에는 포함하지 않습니다.
위 코드는 원본 대조에 필요한 공개 식품 식별자이며 사용자 식별자가 아닙니다.

## 코드 역할과 오류 처리

`backend/prepare_food_sample.py`는 원본 행 선택과 숫자 문자열 변환, 기존 `calculate_nutrient()` 호출을 담당합니다.
원본 행 번호·식품코드·출처·기준일·생성 방법을 결과에 보존합니다. 원본 응답과 계산 결과는 별도 파일로 유지합니다.

- 에너지는 kcal, 단백질·지방·탄수화물·당류·식이섬유는 g, 나트륨은 mg을 유지합니다.
- 빈 문자열·공백 문자열·None은 결과에서 `null`과 `status: missing`으로 표시합니다. JSON의 null은 정보가 없다는 뜻이며 0과 다릅니다.
- 원본 숫자 0은 결과 0과 `status: available`로 유지합니다.
- 숫자가 아닌 표기·음수·NaN·무한대는 오류 처리합니다. 열 자체의 누락도 오류 처리합니다.
- 선택 개수 부족이나 선택 식품코드 중복은 오류 처리합니다. 임의로 채우지 않습니다.
- 기존 결과 파일은 덮어쓰지 않습니다. 합산·건강 판정·반올림 표시 정책은 이번 범위에 없습니다.

## 실행 방법

프로젝트 루트에서 실행합니다. 원본은 Git에 없으므로 로컬에 확보한 파일이 필요합니다.

```bash
.venv/bin/python -B -m backend.prepare_food_sample \
  data/raw/food-standard-15100064-page1-100-20261105.json \
  data/processed/food-sample-150g-20261105.json
```

실행 결과: `5개 식품의 150g 계산 결과 저장`.
동일 날짜 파일이 이미 있으면 새 출력 파일명을 지정해야 합니다.

## 실제 검증 결과

- `.venv/bin/python -B -m unittest discover -s tests -v`: 기존 7개 + 신규 6개, 총 13개 테스트 통과.
- 신규 테스트에는 가상 행만 사용했습니다. 100mL 제외·선택 순서, 결측/0 구분, mg 보존, 잘못된 숫자·섭취량·누락 열·중복 코드·표본 부족 거부를 검증했습니다.
- 실제 선택 5행 × 7개 성분, 총 35개 결과를 원본과 대조했습니다. 숫자 30개는 표준 라이브러리 Decimal로 원본 값 × 1.5를 별도 계산해 허용 차이 0.000000001 미만으로 일치했습니다.
- 식이섬유 결측 5개는 결과도 null임을 확인했습니다. 결측을 0으로 채우지 않았습니다.
- 원본의 `100g` 기준과 식품코드·행 번호 연결도 확인했습니다.
- 로컬 계산 결과 파일이 Git 제외 대상임을 `git check-ignore`로 확인했습니다.

이는 계산 연결과 값 보존 검증이며 공식 영양 데이터 자체의 실험적 정확성 검증은 아닙니다.
