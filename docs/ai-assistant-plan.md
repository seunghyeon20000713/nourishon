# AI 건강 비서 계획 (로드맵 ②, 2026-11-17)

> **결정(2026-11-17): 무료로 진행.** A(가짜 AI)로 전체 흐름 완성 → Gemini 무료 등급을 설정으로 연결. 하루 질문 수 DB 표 승인. 구현·약관 정리는 [ai-assistant-gemini.md](ai-assistant-gemini.md).

## 0. 한 줄 요약

AI는 **숫자를 계산하지 않는다.** 이미 테스트된 계산 함수를 "도구"로 불러 결과를 받고, 그 결과를 쉬운 말로 **설명만** 한다. 화면에는 AI 문장과 함께 도구가 돌려준 원래 숫자·출처를 따로 보여준다.

> 도구 호출(Tool Calling): AI에게 "이런 함수들이 있다"는 목록을 주면, AI가 질문에 맞는 함수 이름과 날짜 같은 입력값을 고르고, **실제 실행은 우리 서버가** 한다. 계산기를 빌려 쓰는 학생과 비슷하다. 답을 지어내지 않고 계산기 결과를 읽어 준다.

## 1. 최소 기능과 도구 5개

질문 예: "이번 주 나트륨 어때?", "어제 단백질 충분해?", "이번 달 운동 얼마나 했어?"

| 도구 | AI가 고르는 입력 | 하는 일 | 재사용할 코드 |
| --- | --- | --- | --- |
| `get_period_nutrition` | 시작일·종료일(최대 31일) | 기간 영양 합계, 기록한 날 N일 / 전체 M일, 기록일 평균, 성분별 누락 수 | **새로 서버로 옮김**: 지금은 화면 `PeriodAnalysis.tsx`에 있음 → `backend/period_summary.py` + 화면과 같은 사례 테스트 |
| `get_day_meals` | 날짜 | 그날 끼니별 음식·섭취량·합계, 미기록 여부 | 저장된 식사 기록(`calculate_meal` 결과) |
| `get_nutrition_review` | 시작일·종료일 | 에너지 비율·참고 범위, 나트륨 기여 식품, 누락·불일치 시 판단 보류 | `backend/nutrition_review.py` `review_nutrition` |
| `get_activity_summary` | 시작일·종료일 | 운동 기록 건수·시간·소모량 추정 합계(표준 MET) | `backend/activity_log.py` 저장 결과 |
| `get_my_reference` | 없음 | 현재 프로필의 유지 에너지 추정·단백질 참고값·나트륨 기준(WHO 2,000mg 미만)과 출처 | `backend/profile.py` `estimate_profile`, `backend/references.py` |

- 도구에는 **사용자 ID·프로필 ID 입력이 없다.** 서버가 로그인 세션에서 본인 프로필을 넣는다. AI가 다른 사람 기록을 요청할 방법 자체가 없게 만든다.
- 도구 결과는 이미 결측과 0을 구분한다("누락 N개", "N일 중 M일 기록"). AI 설명에 이 표현을 그대로 쓰게 한다.
- 단계: ① 서버 함수와 테스트(돈 0원) → ② 가짜 AI(정해진 답을 내는 테스트용)로 대화 흐름·안전장치 테스트(돈 0원) → ③ 실제 AI API 연결(아래 결정 후).

## 3. 무료 원칙과의 충돌 — 개발자 결정 필요

| 선택지 | 비용 | 장점 | 단점·위험 |
| --- | --- | --- | --- |
| A. 가짜 AI로 먼저 완성(추천 시작점) | 0원, 계정 불필요 | 도구·안전장치·화면·테스트를 모두 만들 수 있음. 면접에서 설계 설명 가능 | 실제 대화는 안 됨 |
| B. Gemini 무료 등급(개발용, 가상 데이터만) | 0원, 카드 없이 시작 | 실제 AI 연결 시연 가능 | 입력이 제품 개선·사람 검토에 쓰임, 약관상 민감·개인 정보 금지·의료 조언 금지 → **지인 공개용으로 쓰면 안 됨**. 외부 계정 연결 필요 |
| C. 유료 API(Haiku 5.5 / gpt-5-nano 등) + 월 상한 | 월 약 $1~3 예상, 선불 최소 약 $5 가능성 | 데이터가 학습에 쓰이지 않는 조건, 지인 공개 가능 | **카드 등록·개발자 돈 필요** → 무료 원칙 위반 |

추천: **A로 전체를 완성**하고, 실제 연결은 개발자가 B(개발 중 가상 데이터만) 또는 C를 고른 뒤 진행한다. A의 구조(도구·안전장치)는 어떤 회사 API를 고르든 그대로 쓴다.

## 4. 안전장치

- **진단·처방 거절**: AI 호출 전에 서버가 질문을 검사(약·질환명·증상·"진단해줘" 등)해 정해진 안내(전문가 상담 권유)로 답하고, AI 안내문에도 같은 규칙을 둔다. 테스트: 진단 요구 질문 목록 → 항상 거절 문구, 도구 호출 0회.
- **숫자 보호**: 화면의 숫자는 도구 결과에서 직접 그린다. AI 문장 속 숫자가 도구 결과에 없으면 경고하고 숨기는 검사(테스트로 확인).
- **본인 기록만**: 도구 입력에 사용자·프로필 ID 없음, 서버가 세션에서 주입. 테스트: 사용자 A로 로그인해 B의 프로필 ID를 넣은 요청 → 403, 도구는 A 기록만 읽음.
- **하루 질문 수 제한**: 사용자별 하루 20개(제안). 기존 로그인 시도 제한 표(`auth_attempts`) 구조를 재사용하거나 작은 표 추가 → **DB 변경이라 별도 승인**.
- **월 비용 상한 2중**: ① API 회사 콘솔의 월 지출 한도(예: $5) ② 서버가 응답의 사용 토큰 수를 누적해 월 예산을 넘으면 AI 기능을 끄고 "이번 달 사용량을 모두 썼어요" 안내.
- **API 키**: Render 환경변수(비밀 설정)에만. Git·채팅·스크린샷 금지. 로그에 질문 원문·키를 남기지 않음.
- **기록 보관**: 대화 내용은 기본 저장하지 않음(건강 정보). 필요하면 별도 동의 후.

## 5. 화면

- 메뉴에 **"건강 비서"** 화면 추가(데스크톱 왼쪽 메뉴, 모바일 상단 메뉴). 모바일 아래 4칸 메뉴는 그대로 둔다.
- 대시보드 "오늘 살펴볼 점" 카드에 **"AI에게 물어보기"** 버튼과 예시 질문 3개(누르면 바로 질문).
- 답변 카드 = AI 설명 + **"계산 근거" 접기**(도구가 돌려준 숫자 표, 기간·기록일 수·누락 수, 출처·버전).
- 항상 보이는 안내: "기록된 값만 설명하며, 진단이나 치료를 대신하지 않습니다." / 남은 질문 수 표시.
- 로그인 사용자만(본인 기록 확인 필요). 체험판(Sites)에서는 가짜 AI 예시 답변만.
