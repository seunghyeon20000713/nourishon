# 공공 API 종류별 100개 수동 수집

실행일: 2026-11-05. Python 3.12.3 가상환경 사용. 외부 라이브러리 설치 없음.

## 목적과 선택

첫 3개 응답은 인증 확인용이므로 음식 종류별 검색·계산 연결 검증에 사용할 수 있도록 표본을 확장했습니다.
전체 수집 전 기본 5개 분류에서 첫 페이지 20개씩 받습니다. 이는 프로젝트가 정한 검증 표본이며 전체 식품의 대표 표본이나 무작위 추출이 아닙니다.
사용자가 전체 수집도 허용했지만 이번 실행은 100개에 한정했습니다.

[공식 API 명세](https://www.data.go.kr/en/data/15127578/openapi.do)에 안내된 `FOOD_CAT1_NM` 필터로 요청하고, 실제 응답 분류가 요청 분류와 일치하는지 확인했습니다.
기존 통합표준 다운로드 표본과 이번 인증 API 표본은 별도 원본으로 보관합니다.

## 실행 방법

로컬 `.env`의 `DATA_GO_KR_SERVICE_KEY`를 설정한 뒤 프로젝트 루트에서 직접 실행합니다. 키 값은 출력하거나 명령 인자로 받지 않습니다.

```bash
# 기본 5개 분류 × 20개: 최대 100개
.venv/bin/python -B -m backend.collect_food_api

# 한 분류의 다음 페이지를 확인하는 예시 (이번 실행에서는 미수행)
.venv/bin/python -B -m backend.collect_food_api --category 밥류 --size 20 --page 2
```

`--category`는 반복할 수 있습니다. `--size`는 분류별 1~100개, `--page`는 양의 정수입니다.
분류별 요청을 한 번씩 수행하며 전체 페이지를 자동 순회하거나 주기적으로 실행하지 않습니다.
분류별 결과가 요청량보다 적을 수 있으므로 최종 수신 건수와 고유 코드 수를 확인해야 합니다.

## 실제 수집 결과

| 요청 분류 | 이번 수신 | 응답이 보고한 해당 분류 전체 결과 수 |
|---|---:|---:|
| 밥류 | 20 | 419 |
| 국 및 탕류 | 20 | 505 |
| 면 및 만두류 | 20 | 330 |
| 채소류 | 20 | 580 |
| 과일류 | 20 | 248 |

- 수신 100개, 고유 식품코드 100개, 중복 코드 0개.
- 실제 분류는 요청한 5개 분류와 일치했습니다.
- 데이터 구분 `DB_GRP_NM`: 음식 61개, 원재료성 39개.
- 기준량 `SERVING_SIZE`: 100g 100개.
- `UPDATE_DATE`: 2025-01-23 61개, 2026-07-23 39개.
- 성분 필드는 항목당 `AMT_NUM*` 157개입니다. 필드가 존재해도 값이 모두 채워졌다는 뜻은 아닙니다. 의미·단위별 결측률 분석은 다음 단계입니다.

전체 결과 수와 건수는 수집 당시 응답 값이며 이후 조회 시 달라질 수 있습니다. 원재료성 식품도 조리·가공 상태를 구별해야 합니다.

## 저장과 실패 처리

이번 로컬 저장 폴더: `data/raw/mfds-api-20261105-171230-449195/`.

- 분류별 원본 JSON 5개와 `manifest.json` 수집 기록을 보존했습니다. 재실행하면 새 시각의 폴더가 생깁니다.
- 수집 기록에는 키 없는 요청 주소·분류·페이지·건수·수집 시각·각 원본 SHA-256과 실제 분류·기준량 분포가 들어갑니다.
- 요청 페이지 완료는 `completed_requested_pages`이며 `full_collection_complete`는 항상 false입니다. 전체 수집 완료로 오해하지 않게 구분했습니다.
- 중간 실패 시 성공한 원본을 보존하고 `failed` 상태를 기록합니다. 기존 검색·계산용 데이터는 변경하지 않습니다.
- 중복 코드·응답 분류 불일치·잘못된 응답·키가 포함된 응답은 거부합니다. 숫자로 보이는 영양성분을 임의 해석하거나 결측을 0으로 바꾸지 않습니다.
- HTTP 오류는 상태 코드만, 기타 연결 오류는 안전한 안내만 표시합니다. 키를 포함한 URL이나 서버 응답 원문은 오류로 출력하지 않습니다.
- `.env`와 전체 수집 폴더는 Git 제외 대상입니다.

## 검증

`.venv/bin/python -B -m unittest discover -s tests -v` 결과: 기존 26개 + 신규 7개, 총 33개 통과.
수집 테스트는 실제 키 없이 가상 응답으로 인코딩 처리, 오류에서 키 미노출, 원본 보존·덮어쓰기 방지, 부분 실패 기록, 분류 불일치·키 반사 응답·중복 코드 거부를 검증합니다.
별도로 위 5개 실제 API 요청에서 100개 수신과 코드 중복 없음, 분류·기준량 분포를 확인했습니다.
