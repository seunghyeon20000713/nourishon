# 추후 개선 (백로그)

지인 피드백과 점검에서 나온 과제 중 **아직 코드로 고치지 않은 것**을 모아 둔다. 처리하면 날짜·커밋과 함께 이 문서에서 옮긴다.

## 1. '베지밀 고단백 두유'가 검색되지 않음 — mL 기준 식품 (2026-11-17 기록)

**상황**: 지인이 '베지밀 고단백 두유'를 검색했지만 결과가 없었다.

**확인한 사실 (로컬, 2026-11-05 수집 원본 기준)**
- 원본 API 자료에는 '베지밀' 포함 식품이 56개, 그중 38개가 **100mL 기준**이다. '베지밀 고단백' 6개는 모두 100mL 기준이다(예: 베지밀 고단백 두유 검은콩 팩, 베지밀 고단백 두유 플레인).
- 서비스는 **100g 기준 식품만** 검색·계산한다. 정제 과정에서 100g이 아닌 기준 50,723행(그중 100mL 50,661행)을 분리 파일 `excluded-basis.jsonl`로 뺐다(코드만 보관).
- 이유: 도메인 원칙상 100mL를 밀도 없이 g로 바꾸지 않는다. 두유·우유·음료는 밀도가 1이 아니다.

**검토할 개선 방향**
- mL 기준 식품을 별도로 보관하고, 섭취량을 **mL로 입력**받아 `100mL당 성분 × 섭취량(mL) ÷ 100`으로 계산(밀도 환산 없음).
- 검색 결과에 기준량(100g / 100mL)을 표시하고, 한 끼 합계에서 단위가 섞여도 성분 합계는 같은 단위(kcal·g·mg)라 더할 수 있는지 계산 규칙 확인.
- 필요한 일: 정제 스크립트에서 100mL 행 보존, 카탈로그·API의 기준량 필드, 식사 기록 화면의 단위 선택, 테스트(100g·100mL 혼합 한 끼).
- 영향: 데이터 크기 증가(약 5만 행) → 무료 서버 메모리·디스크 확인 필요.

## 2. 운동 종류 다양화 + 운동 이름 검색·최근 운동 바로가기 (2026-11-17 기록)

**상황**: 등산을 추가했지만(28개), 수영·줄넘기·계단 오르기 등 일상 운동이 더 필요하다는 의견.

**원칙**: 2024 Adult Compendium 공식 코드·MET만 사용하고 값을 만들지 않는다. 사용자가 스스로 구분할 수 있는 조건(속도·노력 정도·장비 유무)만 고른다. 추가할 때마다 `activityGuide.ts` 쉬운 이름과 동기화 테스트를 함께 갱신한다.

**검토할 개선 방향**
- 후보 분류 확인: Water Activities(수영), Conditioning Exercise(줄넘기·계단), Dancing, Home Activities 등에서 일반 성인이 구분 가능한 항목.
- 항목이 늘면 3단계 선택이 길어지므로 **운동 이름 검색**(쉬운 이름·공식 이름 모두)을 둔다.
- **최근 운동 바로가기**: 최근 기록한 운동 3~5개를 맨 위에 두어 한 번에 다시 선택.
- 테스트: 검색 결과, 최근 운동이 내 기록에서만 만들어지는지, 서버 목록과 이름표 일치.

## 3. '콜라' 검색 시 일반 음료가 없음 (2026-11-17 기록)

- 수집 데이터에는 '콜라'로 끝나는 일반 음료(음식 D·원재료 R)가 없고, 대부분 젤리·사탕 같은 가공식품이다. 순위 조정으로는 해결되지 않는다(면접 노트 12 후속).
- 1번(100mL 기준 식품) 지원 시 음료가 함께 포함되는지 다시 확인한다.

## 4. 실제 서버 검색 속도 약 1.5~2초 (2026-11-17 기록)

- Render 무료 서버(0.1 CPU)에서 검색 1회에 약 1.4~1.8초(네트워크 제외, 3회씩 측정). 로컬은 약 0.1초.
- 원인: 검색마다 SQLite 임시 파일 290,871행을 `instr`로 모두 훑는다.
- 검토: SQLite FTS5(전문 검색 색인)의 trigram 토크나이저로 부분 일치 색인 → 메모리·디스크 증가와 순위 규칙 유지 여부를 측정한 뒤 결정. 검색어 입력 중 요청 취소(이미 구현)와 최소 글자 수 안내도 함께 검토.

## 5. Gemini 연결을 Interactions API로 옮기기 (2026-11-17 기록)

- 현재는 `generateContent`(공식 문서상 계속 지원, "legacy")를 쓴다. Google은 새 개발에 Interactions API를 권장한다.
- 제공자 분리 구조라 `GeminiProvider`만 바꾸면 된다. 바꿀 때 thoughtSignature·호출 id 처리와 외부 전송 내용 테스트를 함께 옮긴다.
