# 식사·신체·운동 연결 안내: 첫 단계

로컬 ‘생활 개선’에 최근 7일의 등록 기록과 현재 입력 조건을 묶는 안내를 추가했다. `POST /nutrition/weekly-guidance`가 계산을 담당하며 LLM은 사용하지 않는다. 결과를 저장하거나 기존 기록을 수정하지 않는다.

## 입력과 기간

조회 종료일 포함 최근 7일만 집계한다. 현재 화면은 오늘 기준이다. 날짜가 붙은 식품별 섭취 스냅샷, 신체 측정, 실제 운동 기록, 현재 프로필·운동 가능 조건을 입력한다. 범위 밖 기록은 제외한다. 미래 종료일과 중복 ID·잘못된 단위는 거절한다. 원래 기록의 식품별 정보가 없으면 상세 검토 보류로 집계한다.

## 연결하는 방식

- 식사: 기록 건수·날짜 수·검토 가능 날짜를 표시한다. 일별 나트륨은 기존 영양 검토 코드로 식품별 값에서 다시 계산하며, 하루 확인된 값만으로 2,000mg 이상이면 다음 식사의 국물·소스·영양표시 점검을 안내한다. 결측을 0으로 바꾸지 않는다.
- 단백질: 완전한 열량·주요 성분 자료와 4·4·9 검토를 통과한 기록에서 비율이 낮은 날짜가 2일 이상이면 단백질 급원을 살펴보도록 안내한다. 식품별 정보 없는 식사가 섞인 날짜는 이 패턴에서 제외한다. 2일은 제품의 안내 발생 규칙이며 공식 결핍 진단 기준이 아니다.
- 신체: 기간 내 항목별 첫날·마지막 날 차이를 표시한다. 서로 다른 날짜의 측정 2회가 없으면 보류한다. kg과 체지방률 %p를 구분한다. 식사·운동의 효과로 단정하거나 이 차이만으로 활동량을 조절하지 않는다.
- 운동: 실제 기록 시간과 근력 기록일을 연결한다. 식품 칼로리·BMI·체성분으로 필수 운동 시간을 계산하지 않는다. 기존 일반 성인 시작 초안 함수를 재사용해 본인이 입력한 현재 활동량·경험·가능 시간으로 활동 시간을 제시한다. 기록과 입력 활동량의 차이는 근거에 드러내며, 기록이 불완전할 수 있으므로 자동 증량하지 않는다.
- 증상·제한: 운동 조건에 증상·제한이 있으면 운동 시간 대신 평가 안내를 우선한다. 프로필·운동 조건이 없으면 먼저 입력하도록 연결한다.

전체 기록이 없어도 미기록을 실제 섭취·운동 0으로 해석하지 않는다. 알레르기·가격·재고·질환별 치료식·개별 중량/세트 처방은 이번 범위가 아니다. 현재 관리 방향은 보여주되 감량·증량 열량을 자동으로 처방하지 않는다.

## 화면과 출처

‘생활 개선 → 최근 7일, 다음 실천 정하기’에서 요약·실천 카드·안내 이유·신체 변화·판단 한계를 확인한다. 각 카드에서 식사 기록·운동 조건·신체 정보 화면으로 이동할 수 있다. 오류 시 기록은 유지하고 다시 확인하는 버튼을 제공한다. 개인 응답 캐시 금지·요청 크기 제한·입력값을 복사하지 않는 오류 응답을 적용한다.

참고: [WHO Healthy diet](https://www.who.int/news-room/fact-sheets/detail/healthy-diet), [WHO 성인 신체활동 지침](https://www.who.int/europe/news-room/fact-sheets/item/physical-activity), [2025 한국인 영양소 섭취기준 공개 발표](https://www.kns.or.kr/fileroom/fileroom_view.asp?BoardID=Kdr&idx=168). 출처의 버전·적용 대상·확인일은 기존 출처 레지스트리에서 제공한다.

## 배포 구분

이번 단계는 로컬 실제 기능을 연결한 것이다. 공개 Sites 체험판에는 실제 통합 추천 서버가 연결되어 있지 않으며 이번 작업에서 공개 체험판을 재배포하지 않았다. 체험 모드에서 새 안내를 실행하더라도 실제 기록을 서버로 보내지 않고 미제공 설명을 표시한다.

## 실제 검증 결과

- Python 전체 106개 통과(1.364초). 이후 API 캐시·개인 입력 비노출 검사를 추가해 통합 안내/API 관련 18개 통과(0.208초).
- 프런트엔드 빌드 통과, 브라우저 전체 22개 통과(36.2초).
- 실천 버튼 화면 이동 검사를 추가한 뒤 해당 시나리오 1개 통과(2.4초). 처음 시나리오의 운동 기록에 상세 계산 스냅샷이 없어 상세 화면에서 실패한 문제는 완전한 가상 스냅샷을 넣어 해결했다.
- 단위·기간 필터·레거시 기록·0분·같은 날짜 측정·증상 보류·음식/체중 변화에 따른 운동 자동 증량 방지·API 오류 시 기록 유지·모바일을 검증했다. 390px 캡처도 직접 확인했다.
