# 실천 안내에서 실제 식품 선택으로 연결

로컬 ‘생활 개선’의 식사 관련 안내에 ‘관련 음식 비교’를 추가했다. 나트륨 안내는 나트륨, 단백질 안내는 단백질, 일반 식품 구성·기록 안내는 식이섬유 비교 화면으로 이동한다. 이는 비교할 성분의 초기 선택이며 개인 적합성을 판정한 음식 자동 추천이 아니다.

## 조회·비교

`GET /foods/compare?q=...&focus=protein|fiber|sodium&offset=0&limit=8`가 로컬 정제 식품 목록을 사용한다. 별도 공공 API 호출·데이터 재수집·외부 업로드는 없다.

- 사용자가 입력한 음식명에 일치하는 **전체 검색 결과 안에서** 단백질·식이섬유는 내림차순, 나트륨은 오름차순 정렬한다.
- 정렬 후 페이지를 선택하므로 원본 첫 8개만 정렬하는 방식이 아니다. 동점은 원본 순서를 유지한다.
- 모든 성분은 100g 기준이다. 열량 kcal, 단백질·식이섬유 g, 나트륨 mg을 구분한다. 0은 값으로 포함하고 누락은 ‘정보 없음’으로 표시하며 뒤에 둔다.
- 식품 코드·출처명·자료 기준일·갱신일을 표시한다. 없는 날짜·출처를 만들어 채우지 않는다.
- 전체 식품군의 건강 순위를 산출하거나 ‘고단백·저나트륨’ 영양표시 기준을 충족한다고 판정하지 않는다. 같은 이름의 검색 결과라도 제품·조리 상태가 다를 수 있음을 안내한다.
- 알레르기·질환별 적합성·맛·가격·재고를 확인하지 않은 개인 맞춤 음식 처방은 제공하지 않는다.
- API는 한 번에 최대 20개, offset 최대 10,000으로 제한한다. 화면은 페이지당 8개다. 비교 후보가 매우 많으면 음식명을 구체적으로 입력해야 한다.

## 선택 후 실제 섭취량

‘식사 계산에 담기’는 식품 코드를 기존 장바구니로 전달한다. 이후 기존 식사 계산 화면에서 실제 먹은 g을 입력하고 계산·기록한다. 초기 100g은 편의상 계산 입력값이며 권장 1회 제공량이 아니다. 이미 담긴 식품을 중복 추가하지 않고, 기존 담긴 음식·섭취량은 유지한다. 100개 제한도 기존 규칙을 따른다.

## 정확성·오류 처리

API는 기존 100g 환산 코드를 사용해 비교 값을 준비한다. 쿼리 공백·미지원 성분·범위 초과는 거절한다. 원본 식품 행 위치도 유지한다. 검색 결과 없음·연결 오류를 표시한다. 비교 성분 변경·화면 이탈·프로필 전환 시 이전 요청을 중단해 다른 조건의 결과를 새 조건처럼 표시하지 않는다.

## 적용 범위

이번 기능은 로컬 실제 기능에 추가했다. 공개 Sites 체험판은 실제 식품 비교 API에 연결하지 않았으며 이번 작업에서 재배포하지 않았다. 체험 모드에서는 미연결 안내만 제공한다. 실제 기능 외부 테스트를 위한 서버·DB 연결은 후속 단계다.

## 실제 검증 결과

서버 전체 **108개 통과(1.437초)**, 프런트엔드 빌드 통과, 브라우저 전체 **24개 통과(38.7초)**. 가상 자료로 성분 순서·0과 누락·자료 기준과 페이지를 검증했고, 실제 로컬 식품 검색 → 비교 → 코드 전달 → 150g 계산 → 기록까지 확인했다. 결과 없음·연결 오류·모바일 가로 넘침도 검사했다. 모바일 캡처를 확인한 뒤 좌우 스크롤로 성분·담기 버튼을 볼 수 있다는 안내를 추가하고 최종 빌드를 통과했다. 실제 식품 원본·정제본은 커밋하지 않았다.
