# 화면·영양 참고값·개인 프로필 개선 · 2026-11-06

## 참고한 서비스와 적용한 선택

- [Cronometer 대시보드 공식 안내](https://support.cronometer.com/hc/en-us/articles/10570212821268-Dashboard): 하루 현황과 목표·변화 정보를 빠르게 확인하는 구성.
- [MyFitnessPal 오늘 화면 공식 안내](https://support.myfitnesspal.com/hc/en-us/articles/39985611667341-Your-Today-tab): 식사별 기록과 추가 동선을 한 화면에서 제공하는 구성.

NourishOn에는 날짜별 요약 카드, 식사별 바로가기, 프로필·기록 분석 이동을 적용했습니다. 외부 사이트의 이미지·브랜드·디자인 파일은 복사하지 않았습니다. 가격·추천 효과·사용자 수를 만들지 않았습니다.

미기록일은 열량 0으로 표시하지 않으며, 기록에 누락이 있으면 함께 표시합니다. 추정 유지 에너지 대비 비율은 기록 현황이며 남은 권장 섭취량·감량 처방으로 표시하지 않습니다. 과거 날짜의 비율도 현재 프로필 참고값에 대한 것이며 과거 목표 이력은 아직 없습니다.

## 영양 기준 보완

[한국영양학회의 보건복지부 공식 발표문](https://www.kns.or.kr/fileroom/fileroom_view.asp?BoardID=Kdr&idx=168)에서 2025 한국인 영양소 섭취기준 개정을 확인했습니다. 일반 성인 참고 에너지 적정비율을 탄수화물 50~65%, 단백질 10~20%, 지방 15~30%로 관리합니다.

환산식: 추정 유지 에너지 × 비율 ÷ 성분별 열량계수. 탄수화물·단백질은 4kcal/g, 지방은 9kcal/g입니다. 성분별 범위를 각각 계산하며 모든 상한을 동시에 권장하는 의미가 아닙니다. API 응답에 출처·버전·단위를 포함합니다.

유지 에너지는 기존 북미 DRI 2023 공식입니다. 한국인 개인 에너지 처방으로 검증했다고 표시하지 않습니다. 단백질 0.8g/kg 일반 참고값, WHO 식이섬유·나트륨 지침, KDRI 에너지 비율은 적용 근거가 서로 다르므로 분리해서 표시합니다. 한국인 성별·연령별 세부 표 전체를 적용한 상태는 아닙니다.

## 체중·체성분 이력

프로필 적용 시 측정일·체중과 선택 체성분 값을 이력으로 남깁니다. 같은 측정일·값은 중복 추가하지 않습니다. 기존 인바디 값은 첫 갱신 때 이력으로 보존합니다. 미래 측정일, 체중과 체성분 측정일 불일치를 거부합니다.

체중 그래프와 원본 표는 기록값을 보여줍니다. 첫 기록 대비 차이를 표시하지만 건강 개선 판정은 하지 않습니다. 그래프의 가로 간격은 측정 순서이며 실제 날짜 간격이 아닙니다. 체성분 값을 유지 에너지 공식에 넣거나 정확도 향상을 보장하지 않습니다.

## 개인 사용자 프로필 등록

- 별칭·고유 식별자(UUID)로 로컬 프로필을 등록하고 전환합니다. 실명·이메일·비밀번호는 요구하지 않습니다.
- 각 프로필에 기본 정보·참고값·측정 이력·식사 기록을 연결합니다.
- 전환 시 작성 중인 음식 선택과 계산 결과를 초기화해 다른 프로필에 잘못 기록되는 것을 방지합니다.
- 기본은 실행 중에만 유지합니다. 보관을 선택하면 모든 로컬 프로필이 같은 브라우저 저장소에 암호화 없이 남습니다.
- 이전 단일 프로필 저장 형식은 기록을 유지한 채 첫 로컬 프로필로 옮깁니다. 읽지 못한 저장 형식은 자동 덮어쓰지 않습니다.

이 기능은 계정 가입·로그인·권한 검증이 아닙니다. 같은 기기에서 누구나 프로필을 전환할 수 있습니다. DB 저장 단계에서는 사용자 소유권과 인증을 별도로 구현해야 합니다.

## 다음 기록 관리 단계

PostgreSQL 도입 시 다음 관계를 유지합니다. 아직 DB 테이블을 생성하거나 개인 데이터를 서버에 저장하지 않았습니다.

| 계획 테이블 | 역할과 연결 |
| --- | --- |
| users | 내부 사용자 식별자, 이후 인증 계정과 연결 |
| profiles | 사용자에 속한 기본 정보·관리 방향 |
| body_measurements | 프로필별 측정일·체중·체성분 이력 |
| nutrition_target_versions | 프로필별 기준 출처·버전·계산 입력·참고값 스냅샷 |
| meals / meal_items | 프로필별 식사일·구분과 당시 식품·섭취량·영양값·출처 |

인증 전까지 로컬 개발로 제한하며, 공개 회원가입·DB 외부 공개·배포는 별도 단계입니다.

## 검증

가상 프로필 두 개를 생성하여 식사·측정값이 섞이지 않는지, 새로고침 후 선택 보관된 프로필이 유지되는지 검사합니다. 기존 저장 형식 이전과 보관 해제, 390px 모바일 화면, 체중 변화, 에너지 비율 환산과 날짜 검증도 검사합니다. 스크린샷은 `/tmp`에만 보관합니다.

최종 실제 실행 결과: 백엔드 unittest 67개 통과, Playwright 브라우저 9개 시나리오 통과, TypeScript 검사·Vite 빌드 통과. 데스크톱·390px 모바일 스크린샷과 가상 측정 이력 화면을 확인했습니다. 이전 저장본 보호 검사는 지원하지 않는 형식이 로컬 프로필 등록만으로 덮어써지지 않는지 확인했습니다. 사용성 개선 효과와 건강 성과는 측정하지 않았습니다.
