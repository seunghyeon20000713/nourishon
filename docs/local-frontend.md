# 로컬 프론트엔드 첫 화면

구현·검증일: 2026-11-05. 외부 호스팅이나 배포 없이 로컬에서 실행합니다.

## 지금 가능한 흐름

[프론트엔드](http://127.0.0.1:5173/)에서 음식 검색 → 추가 → 섭취량(g) 수정 → 영양 합계 계산을 사용할 수 있습니다.
기존 FastAPI가 정제한 100g 기준 식품 290,871개를 검색하고 계산합니다. 프론트엔드에 전체 데이터를 넣지 않습니다.
이전에 안내한 8000/docs는 API 테스트 화면이며, 사용자가 조작하는 첫 화면은 5173입니다.

- 검색어 입력과 추천 검색어 버튼, 결과 페이지 이동, 중복 추가 방지
- 선택한 음식의 섭취량 수정·삭제와 입력 검증
- 열량·단백질·지방·탄수화물·당류·식이섬유·나트륨 표시
- 결측은 정보 없음, 일부 결측은 확인된 값의 합계와 누락 개수 표시
- 음식·섭취량 변경 시 이전 결과를 지우고 진행 중 요청을 취소해 오래된 결과 표시 방지
- 빈 검색 결과·서버 연결 오류·잘못된 섭취량·계산 대기 상태 안내
- 모바일에서는 화면을 세로로 배치하고 입력과 결과를 순서대로 확인

개인 영양 목표를 아직 계산하지 않으므로 임의의 목표량·달성률·식사 점수는 표시하지 않습니다.
내 몸과 목표·생활 개선 메뉴는 예정 상태로 비활성화했습니다. 인바디 입력·개인 목표·추천은 아직 구현하지 않았습니다.

## 실행 방법

먼저 [로컬 API 안내](local-api.md)대로 백엔드를 실행합니다. 실제 정제 데이터가 로컬에 필요합니다.

```bash
.venv/bin/python -B -m uvicorn backend.api:app \
  --host 127.0.0.1 --port 8000 --no-access-log
```

다른 터미널에서 프론트엔드를 실행합니다.

```bash
bash scripts/frontend.sh dev
```

브라우저에서 **http://127.0.0.1:5173/** 을 엽니다. 음식명으로 `국밥_돼지머리`를 검색하고 추가한 뒤 150g으로 계산하면 열량 205.5kcal를 확인할 수 있습니다. 권장 식사량이 아닌 검증 예시입니다.
현재 서버가 실행 중이면 같은 명령을 다시 실행할 필요가 없습니다. 사용자가 터미널에서 실행한 서버는 해당 터미널에서 Ctrl+C로 종료합니다.

### Node.js와 재현

환경에 Node.js·npm이 없어 [Node.js 공식 배포](https://nodejs.org/dist/index.json)의 24 LTS 계열 v24.22.2 Linux x64를 준비했습니다.
배포 파일의 SHA-256을 공식 SHASUMS256.txt와 대조한 뒤 프로젝트의 Git 제외 폴더 `.tools/`에 풀었습니다. 시스템 Node.js 설정은 변경하지 않았습니다.
실행 스크립트는 시스템 Node.js가 있으면 사용하고, 없으면 이번 `.tools` 실행 환경을 사용합니다.

다른 컴퓨터에서는 Node.js 24 LTS를 설치한 뒤 다음처럼 재현할 수 있습니다.

```bash
cd frontend
npm ci
npm run dev
```

React 19.3.1, TypeScript 7.0.2, Vite 8.3.6을 사용했습니다. 정확한 버전과 간접 의존성은 package-lock.json에 고정했습니다.
`frontend/.nvmrc`에도 검증한 Node.js 버전을 기록했습니다.

## 파일 역할

| 파일 | 역할 |
|---|---|
| frontend/src/App.tsx | 검색·음식 목록·섭취량·결과 화면과 API 요청 |
| frontend/src/styles.css | 화면 배치·색상·모바일 대응 |
| frontend/src/fonts.ts | 로컬 글꼴 자산과 한글 하위 글꼴 경로 연결 |
| frontend/vite.config.ts | 로컬 서버와 /api → 백엔드 프록시 |
| frontend/tests/meal.spec.ts | 브라우저의 실제 클릭·입력·계산 검증 |
| scripts/frontend.sh | 프로젝트 실행 환경을 선택해 npm 명령 실행 |

## 개인정보와 공개 범위

- 프론트엔드는 `/api`로 요청하고 Vite가 127.0.0.1:8000에 전달합니다. 공공 API 키가 브라우저에 전달되지 않습니다.
- 루트 `.env`를 프론트엔드에서 읽거나 번들에 포함하지 않습니다. 개발 서버에도 환경 파일·인증 파일·원본 데이터 경로 차단 규칙을 명시했습니다.
- 입력한 음식과 섭취량은 브라우저 메모리에만 있습니다. 새로고침하면 초기화되며 localStorage·파일·DB에 저장하지 않습니다.
- 폰트는 공개 Fontsource 패키지의 자산을 로컬에서 제공합니다. 기본 프론트엔드 화면은 Google Fonts 등 외부 폰트 서버를 호출하지 않습니다.
- `.tools`, node_modules, 빌드 결과, 브라우저 검사 결과, 원본·가공 데이터, `.env`, 인증키는 Git에서 제외합니다.
- 이번 공개 대상은 프론트엔드 코드·가상 테스트·의존성 목록·문서입니다.

## 실제 검증과 오류 해결

- `bash scripts/frontend.sh build`: TypeScript 검사와 Vite 빌드 통과.
- Playwright Chromium의 1440px 데스크톱·390px 모바일 검증을 포함한 5개 시나리오 통과.
- 실제 백엔드에서 검색 → 추가 → 150g 계산 → 입력 변경 시 결과 초기화 → 삭제를 확인했습니다.
- 가상 응답으로 결측·부분 결측·숫자 0 구분, 검색 결과 없음·오류 안내, 페이지 이동·빈 섭취량 거부를 확인했습니다.
- 모바일에서 실제 계산과 가로 넘침 없음을 확인했습니다. 데스크톱·모바일 스크린샷도 직접 확인했습니다.
- 첫 화면 검사에서 한글 폰트 URL이 잘못 해석돼 폰트 대신 HTML을 받는 문제를 발견했습니다. Vite 자산 URL을 명시적으로 매핑하고 폰트 로딩·콘솔 오류 검사를 추가해 통과했습니다.
- 자동 브라우저 실행에 필요한 Linux 라이브러리 일부가 없었습니다. 테스트용 패키지를 /tmp에 내려받아 추출하고 실행 시에만 사용했습니다. 시스템 라이브러리를 설치·변경하지 않았습니다.

현재 환경에서 브라우저 검증 재실행 명령:

```bash
LD_LIBRARY_PATH=/tmp/nourishon-browser-libs/usr/lib/x86_64-linux-gnu \
PLAYWRIGHT_BROWSERS_PATH=/tmp/nourishon-playwright \
bash scripts/frontend.sh test:e2e
```

위 /tmp 파일은 이번 환경의 임시 검증 도구입니다. 다른 컴퓨터에서는 Playwright 안내에 따라 Chromium과 해당 운영체제의 브라우저 의존성을 준비한 뒤 `npm run test:e2e`를 실행합니다.
브라우저 검증에는 두 로컬 서버가 실행 중이어야 합니다. 테스트 입력은 공공 식품의 가상 섭취량 또는 가상 식품이며 개인 기록이 아닙니다.
