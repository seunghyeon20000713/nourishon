# 한 끼 영양 합계

검증일: 2026-11-05. Python 3.12.3 가상환경 사용. 추가 라이브러리 설치 없음.

## 이번에 구현한 기능

`backend/meal.py`의 `calculate_meal()`은 식품 원본 행 목록과 식품코드·섭취량(g) 목록을 받습니다.
기존 `select_food()`로 정확한 100g 기준 식품을 선택하고, `prepare_sample()`과 `calculate_nutrient()`로 각 섭취량을 환산합니다.
항목별 원본 행 번호·출처·기준일도 유지합니다. 원본을 변경하거나 입력 식사를 파일·DB에 저장하지 않습니다.

입력 예시는 다음과 같습니다. 실제 사용자 기록이 아닌 실행 확인용입니다.

```python
entries = [
    {"food_code": "P123-205020300-2649", "intake_g": 150},
    {"food_code": "P114-300030000-2318", "intake_g": 50},
]
```

## 합계 규칙

- 성분별 `known_total`은 확인된 값의 합계입니다. 단위를 변환하지 않고 kcal·g·mg을 유지합니다.
- 모든 항목에 값이 있으면 `status: complete`, 일부만 있으면 `partial`, 전부 없으면 `missing`입니다. 이는 데이터의 유무 표시이며 과학적 측정 정확성 평가가 아닙니다.
- 일부 값이 없으면 알려진 값만 더하고 누락 개수를 표시합니다. 이를 완전한 섭취량으로 해석하지 않습니다.
- 전부 결측이면 합계는 `None`이며 ‘정보 없음’을 표시합니다. 0은 유효한 숫자로 유지합니다.
- 같은 음식의 여러 입력은 별도 섭취 항목으로 합산합니다. 누락 개수도 식품 종류가 아니라 입력 항목 기준입니다.
- 0g 입력은 허용합니다. 현재는 원본 성분이 결측이면 0g 항목도 결측 상태를 유지하는 보수적 규칙입니다.
- 빈 식사, 음수·비유한 섭취량, 알 수 없는 코드·100mL 전용 코드·중복 원본 코드, 합계 범위 초과는 거부합니다.
- 합산은 Python 기본 `math.fsum`을 사용합니다. 계산값은 보존하고 터미널 표시만 소수 셋째 자리까지 반올림합니다. 의학적·영양학적 유효 숫자 정책은 아직 정하지 않았습니다.

## 직접 실행

로컬에 기존 공식 표본이 있는 환경에서 프로젝트 루트 기준으로 실행합니다. `--food`를 반복해 음식별 섭취량을 넣습니다.

```bash
.venv/bin/python -B -m backend.meal \
  data/raw/food-standard-15100064-page1-100-20261105.json \
  --food P123-205020300-2649 150 \
  --food P114-300030000-2318 50
```

실제 실행 결과의 합계 부분:

```text
한 끼 영양 합계
열량: 157.5 kcal
단백질: 11.405 g
지방: 4.865 g
탄수화물: 18.61 g
당류: 5.235 g
식이섬유: 정보 없음 (누락 2개)
나트륨: 927 mg
```

이는 권장 식단·실제 개인 식사 기록이 아닙니다. 공식 표본의 확보 경로는 [공공데이터 기록](public-food-data.md)에 있습니다.
개인 식사 기록을 명령어에 입력하면 터미널 기록에 남을 수 있으므로 이 단계에서는 위 검증 예시만 사용합니다.

## 실제 검증

`.venv/bin/python -B -m unittest discover -s tests -v`로 기존 20개 + 신규 6개, 총 26개 테스트가 통과했습니다.
신규 테스트는 가상 식품으로 서로 다른 섭취량의 합산, 단위와 행 번호, 일부·전체 결측과 0 구분, 한글 표시, 0g·동일 식품 반복, 잘못된 입력, 합계 범위 초과를 확인합니다.
추가로 실제 표본 2개 식품의 7개 성분을 Decimal로 별도 계산해 합계와 누락 개수를 대조했습니다. 숫자 결과의 차이는 0.000000001 미만이었습니다.
