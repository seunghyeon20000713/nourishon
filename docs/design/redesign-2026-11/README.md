# 화면 디자인 점검과 개선안 · 2026-11-17

목표: "상업 서비스처럼 보이는 개인 건강 비서". 이번 단계는 **점검과 개선안 제시**까지이며, 코드는 바꾸지 않았다.

## 캡처 방법

- 테스트 서버와 같은 화면(`VITE_NOURISHON_STAGING_NOTICE=1` 빌드)을 로컬 단일 주소 서버로 띄웠다. DB는 **테스트 전용 `nourishon_test`** 를 썼다(개인 기록이 있을 수 있는 로컬 개발 DB와 배포 서버는 쓰지 않음).
- 가상 계정을 만들어 가상 기록을 넣었다. 기록은 체중 4회와 식사 5건이다. 캡처 후에는 탈퇴 API로 계정을 지웠고, 중간 오류로 남은 3개는 테스트 DB에서 따로 삭제했다.
- 데스크톱 1440×900은 전체 페이지, 모바일 390×844는 **첫 화면(스크롤 전)** 으로 찍었다. 상태는 세 가지다. 처음 방문(기록 없음), 기록 있음, 서버 연결 오류(요청 차단으로 재현).
- 도구: Playwright Chromium. 재부팅해도 지워지지 않도록 `.tools/`(Git 제외)에 브라우저와 실행 라이브러리를 두었다.

캡처: [before/](before/) — `desktop-*.png`(전체), `mobile-*-first-screen.png`(모바일 첫 화면)

## 문제점 (우선순위 순)

### P0 — 정확성·신뢰 (디자인과 별개로 먼저 고칠 것)

1. ✅ (2026-11-17 수정) **입력하지 않은 체성분이 대시보드에서 `0.0 kg`로 보인다.** 서버는 빈 값을 `null`로 저장하는데, 대시보드는 `undefined`만 "미등록"으로 처리한다. 그래서 `null`이 0.0으로 바뀐다. "결측과 0은 다르다" 원칙 위반이다. 같은 기록을 "기록 관리" 화면은 "미등록"으로 바르게 보여준다. → [desktop-05-dashboard-data.png](before/desktop-05-dashboard-data.png)
2. ✅ (A) **서버 연결 실패가 화면에 드러나지 않는다.** 오류가 나면 로그아웃된 빈 화면처럼 보인다. 오류 문구는 닫혀 있는 계정 패널 안에만 있다. → [desktop-12-offline.png](before/desktop-12-offline.png)
3. ✅ (A) **문구가 배포 상황과 맞지 않는다.** 소개 화면에 "현재는 로컬 개발용 서비스입니다", 바닥글에 "LOCAL DEVELOPMENT", "일반 성인 로컬 MVP"가 남아 있다. → [desktop-01-intro.png](before/desktop-01-intro.png)

### P1 — 첫 화면에서 할 일이 바로 보이는가, 일관성

4. **처음 사용자의 할 일이 아래에 묻혀 있다.** "처음이라면 여기서 시작하세요"(3단계)가 데스크톱에서는 약 1,050px 아래, 모바일에서는 두 번째 화면 이후에 있다. 첫 화면에는 큰 "— kg"와 "— kcal"만 보여 고장 난 화면처럼 보인다. → [desktop-02-dashboard-empty.png](before/desktop-02-dashboard-empty.png), [mobile-02-dashboard-empty-first-screen.png](before/mobile-02-dashboard-empty-first-screen.png)
5. **상단 메뉴가 중복된다.** 햄버거 버튼이 2개(데스크톱 좌·우, 모바일 위·아래)이고, "내 정보"와 "내 계정/로그인" 드롭다운도 2개다. 여기에 설정 톱니까지 있어 어디를 눌러야 할지 헷갈린다.
6. **모바일 첫 화면의 약 38%(위쪽 약 320px)가 안내 띠·로고 줄·헤더 2줄이다.** 오늘 먹은 열량 같은 핵심 정보는 첫 화면에 없다. → [mobile-05-dashboard-data-first-screen.png](before/mobile-05-dashboard-data-first-screen.png)
7. **화면마다 스타일이 다르다.** 대시보드와 식사 기록은 "저널" 스타일이다. 기록 관리와 운동은 흰 패널에 기본 입력 폼(브라우저 기본 선택 상자, 다른 버튼 모양)을 쓴다. → [desktop-07-history.png](before/desktop-07-history.png), [desktop-09-exercise.png](before/desktop-09-exercise.png)

### P2 — 읽기 편함, 세부

8. 11~12px의 작은 회색 안내문이 많아 대비가 낮고, 핵심 숫자보다 주의 문구가 더 눈에 띈다.
9. 운동 화면에서 자주 쓰는 "실제 운동 기록"이 긴 계획 입력 폼 아래에 있다.
10. 체중 그래프 Y축 눈금(63.1, 62.1, 61.2…)이 깔끔한 숫자가 아니다.
11. 소개 화면의 아래 섹션은 스크롤 애니메이션 전에는 비어 있다(전체 캡처 기준. 실제 스크롤에서는 나타남).

잘 된 점: 식사 기록 화면은 단계(음식 찾기 → 섭취량 → 영양 확인), 검색 결과, 담기 상태가 명확하다. 모바일 하단 메뉴도 손가락으로 누르기 편하다. → [desktop-06-meal-search.png](before/desktop-06-meal-search.png)

## 개선안 3가지

미리보기는 **코드를 바꾸지 않고 캡처할 때만 CSS를 덧씌운 대략적인 모습**이다([options/](options/)의 `option-*-preview.css`). 문구 변경과 위치 재배치는 실제로 구현해야 정확히 보인다.

| | A. 정리형 | B. 카드형 앱 | C. 클린 + 강조색 |
| --- | --- | --- | --- |
| 핵심 | 지금 색·글꼴 유지, 구조와 문구 정리 | A + 화면 공통 디자인 규칙 | A + 흰 배경, 행동 버튼만 주황 강조 |
| 해결하는 문제 | P0 1~3, P1 4~6, P2 8 | A + P1 7(기록·운동 화면 통일), P2 9 | A + "할 일 버튼이 눈에 띄게" |
| 바뀌는 것 | 처음 사용자 3단계를 맨 위로, 빈 값 "—" 대신 안내 문구, 메뉴 하나로 합치기, 모바일 상단 1줄, 오류 띠 표시 | 흰 카드·둥근 모서리·그림자, 버튼 모양·글자 크기 단계 통일, 오늘의 일기 카드 강조 | 배경 흰색, 주요 행동 버튼 주황(#e8673c), 초록은 데이터 표시에만 |
| 위험 | 낮음(기존 화면 구조 유지) | 중간(여러 화면 CSS 변경, 브라우저 테스트 다수 갱신 가능) | 중간(브랜드 색 변경, 공개 체험판과 달라짐) |
| 미리보기 | [데스크톱](options/option-A-desktop-dashboard-empty.png) | [데스크톱](options/option-B-desktop-dashboard-empty.png) | [데스크톱](options/option-C-desktop-dashboard-empty.png) |

모바일 4종 비교(현재·A·B·C): [기록 없음](options/compare-mobile-empty.png), [기록 있음](options/compare-mobile-data.png)

추천: **A를 먼저 적용하고, 이어서 B로 확장한다.** A는 신뢰 문제와 첫 화면 문제를 낮은 위험으로 해결하고, B는 A 위에 공통 규칙을 얹는 구조라 순서대로 하면 되돌리기도 쉽다. C의 강조색은 B를 적용한 뒤 버튼 색만 따로 비교해 보고 정해도 늦지 않다.

## 진행 기록

### 2026-11-17 P0-1 수정: 체성분 null을 "미등록"으로

- 원인: 서버는 입력하지 않은 체성분을 `null`로 돌려준다(Pydantic `model_dump`가 빈 선택값을 `None`으로 저장). 대시보드 `BodyOverview`는 `=== undefined`만 결측으로 봤다. 그래서 `null`이 `number(null)`을 거쳐 `0.0`이 됐다.
- 수정: `BodyOverview.tsx`(요약·표)와 `Wellness.tsx`(로컬 기록 변환)의 검사를 `== null`로 바꿨다. `== null`은 `undefined`와 `null`을 함께 결측으로 본다. 0은 그대로 숫자로 표시한다.
- 테스트: `body-dashboard.spec.ts`에 null 체성분 테스트를 추가했다. **수정 전 코드에서 실패하고 수정 후 통과**하는 것을 확인했다.
- 함께 고친 기존 테스트 3개:
  - `body-dashboard`·`journal`: 날짜가 2026-11-06으로 고정돼 날짜가 지나며 깨졌다(버튼 이름과 선택 날짜가 '오늘' 기준으로 바뀜). 오늘·지난 날짜를 모두 확인하도록 바꿨다.
  - `account`: 2026-11-16 회원 탈퇴를 추가하며 계정 패널 안 `summary`가 2개가 돼 실패했다. 당시 브라우저 실행 환경이 멈춰 놓쳤다. 패널 바로 아래 `summary`만 누르도록 고쳤다.
- 결과(로컬): 브라우저 테스트 27개 통과(API는 테스트 DB에 연결), 백엔드 unittest 통과.

정렬은 눈대중이 아니라 실제 위치를 재서 맞췄다. 데스크톱 상단 바의 버튼 세로 중앙은 98px로 통일했다(계정 버튼만 109px였음). 모바일 390·360px에서는 네 요소의 세로 중앙이 67~69px이고 겹침·가로 넘침이 없다.

작업 중 고친 내 실수 2개:
1. 상단 바를 고정(sticky)하면서 계정 버튼을 덮었다. 캡처 스크립트가 계정 버튼을 누르지 못해 발견했다.
2. 기록 설정 아이콘이 메뉴 버튼과 겹쳤다. 기존 CSS의 더 구체적인 선택자 때문에 내 여백 규칙이 무시됐다. 실측으로 발견했다.

검증(로컬): 브라우저 테스트 29개 통과. 서버 연결 실패 안내(데스크톱·모바일) 2개를 새로 넣었고, 메뉴 구조 변경에 맞춰 `menu`·`journal`·`nutrition`·`meal`·`weekly-guidance` 테스트를 고쳤다. 백엔드 변경은 없다.

### 2026-11-17 A 후속 수정: 모바일 드롭다운이 화면 밖으로 잘림 (개발자 발견)

- 문제 1(개발자가 after-A 캡처에서 발견): 모바일 "내 계정" 패널이 왼쪽 밖으로 잘렸다. 실측으로 390px에서 x −54, 360px에서 x −74였다. 계정 버튼을 오른쪽에서 104px에 고정했는데, 폭 340px 패널을 버튼 오른쪽 끝에 맞춰 펼쳤기 때문이다(390 − 104 − 340 = −54).
- 문제 2(테스트로 함께 발견): 모바일 "기록 설정" 패널이 자기 버튼을 덮어, 같은 버튼으로 다시 닫을 수 없었다. A에서 버튼을 상단 바로 옮기면서 패널 위치를 따라 바꾸지 않았다.
- 수정: 모바일(700px 이하)에서 두 패널을 버튼 위치와 관계없이 화면 양쪽 12px 여백, 상단 바 바로 아래에 고정했다. 내용이 길면 패널 안에서 스크롤된다.
- 테스트 `panels.spec.ts`(1440·390·360px): 로그인 전·후와 회원 탈퇴 항목을 펼친 상태에서 패널이 화면 안에 있는지, 같은 버튼으로 다시 닫히는지 확인한다. 수정 전 CSS에서는 390·360px이 실패하는 것을 확인했다. 가상 계정은 테스트가 끝나면 탈퇴 API로 지운다.
- 결과(로컬): 브라우저 테스트 32개 통과. 캡처: [계정 패널](after-A/mobile-account-panel-fixed.png), [기록 설정 패널](after-A/mobile-settings-panel-fixed.png)

### 2026-11-17 스테이징 배포 확인 (클라우드)

`fac88c6`(개선안 A + 모바일 패널 수정)을 개발자가 Render에 배포했다. 외부에서 확인한 결과, 화면 번들에 새 문구 5종("기록 설정", 연결 실패 안내, 포트폴리오 문구, 모바일 한 줄 안내, 회원 탈퇴)이 있고 CSS에 연결 실패 띠 스타일이 있다.

실제 스테이징 서버에서 데스크톱 4장과 모바일 첫 화면 5장을 찍었다. 기록이 있는 화면은 가상 계정으로 만들었고, 캡처 스크립트는 중간에 오류가 나도 탈퇴하도록 바꿨다. 실제로 두 계정 모두 탈퇴 응답 200을 받았다. 서버 오류 화면은 브라우저에서 API 요청을 차단해 재현했다.
